# ODP 支持 RPC 服务端口

## 背景介绍

OBKV 是 OceanBase 数据库提供的通过 API 接口访问 Table 模型/Hbase 模型的能力，OBKV 为用户提供更加简单高效的 API 访问接口，并且能在单一数据库下提供多种数据模型，满足用户不同场景下数据的多样性需求。

OceanBase 数据库从 V2.x 版本开始支持 OBKV 的能力， 后续在 V3.x、V4.x 等系列版本不断丰富扩展了 OBKV 的处理能力。并且随着 OceanBase 数据库的不断发展，OBKV（TableAPI、HBASE 宽表模型）不仅服务了蚂蚁主站用户，也逐步服务开源、公有云客户，为众多客户提供 no-SQL API 访问 OceanBase 数据库的能力。

OBKV 的详细介绍可参见官网《OceanBase 数据库》文档 [OBKV](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000001049819) 章节。

## 功能介绍

ODP 从服务 OceanBase 数据库开始，仅提供 SQL 服务以及对应的端口，仅支持处理 SQL 相关的协议处理。因此，为将 OceanBase 数据库的 OBKV 能力更好地服务各类客户，ODP 在当前 SQL 服务能力基础上，增加了 RPC 服务端口（默认 `2885`）来提供 no-SQL 请求的代理服务，主要提供如下能力。

* RPC 服务端口：接收和响应用户的所有 no-SQL 请求。

* 请求处理：当前全量 OBKV 请求及相应结果的处理。

* 跨分区请求处理：支持 Batch、Query 等跨分区请求的处理。

* RPC 请求路由转发：处理当前路由能力解放重客户端带来的业务处理压力。

* 安全鉴权、连接控制：支持白名单、连接数并发控制等。

* 旁路导入能力：通过 OBKV 扩展请求支持旁路导入的能力。

## 使用方法

ODP 从 V4.3.0 开始支持同时提供 SQL、RPC 服务能力，并且默认配置启动时，会同时开启 SQL、RPC 服务端口对外提供服务，默认 SQL 服务端口为 `2883`，默认 RPC 服务端口为 `2885`。

### 配置端口

ODP 支持在启动阶段设置 `-s`/`--rpc_listen_port` 自定义指定 RPC 服务端口，比如指定 RPC 服务端口为 `3885`：

<main id="notice" type='explain'>
  <h4>说明</h4>
  <ul>
  <li>
  <p>本节介绍的 ODP 启动命令需要在 ODP 的安装目录下执行。</p>
  </li>
  <li>
  <p>ODP 启动参数可通过 <code>./bin/obproxy -h</code> 命令查看，启动 ODP 的命令介绍也可参见 <a href="200.install/100.install-odp.md">通过命令行部署 ODP</a> 中 <b>启动 ODP</b> 章节。</p>
  </li>
  </ul>
</main>

* 通过 rs_list 启动

  ```shell
  [admin@test obproxy]$ ./bin/obproxy -p2883 -s 3885 -r'10.10.10.1:2881;10.10.10.2:2881' -n test -o enable_cluster_checkout=false,syslog_level=INFO
  ```
  
  此处 `-r` 选项中的配置仅为示例，您需根据实际情况配置为 OceanBase 数据库的 Root Service 列表。

* 通过 obconfigserver 启动

  ```shell
  [admin@test obproxy]$ ./bin/obproxy -p2883 -s 3885 -e -n test -o obproxy_config_server_url='<YOUR_CONFIG_URL>',syslog_level=INFO
  ```

  您需根据实际情况将 `<YOUR_CONFIG_URL>` 修改为 obconfigserver 的 URL 值。

### 关闭端口

可通过配置 `enable_obproxy_rpc_service` 控制是否开启 RPC 服务端口，默认开启 RPC 服务端口，可在启动阶段通过设置 `enable_obproxy_rpc_service` 参数为 `false` 不启动 RPC 服务端口，示例如下：
