# 支持分区计算时等值关系推导

## 背景介绍

ODP V4.3.4 及之前版本中，不支持对以下这类 SQL 计算分区键，即：不支持等值关系的推导，要求 SQL 中必须显式指定分区键及其对应的值。

```sql
#分区表 t1 的分区键为 C1
select * from t1 where C1 = C2 and C2 = 1
```

基于使用的实际需求，ODP 自 4.3.5 版本起支持对 SQL 中的等值关系推导，并使用推导的结果来计算分区。

## 使用限制

* 单个 SQL 中推导的等值关系最多只能有 1024 个。

* 可推导的等值关系包括 `=`、`<=>` 和 IN 表达式的第一个值，不包括大于、小于关系。

* 对于过于复杂的 SQL 可能无法支持完整地推导。

* 对于较长的 SQL，如果 SQL 长度超过了配置项 [request_buffer_length](../../400.configuration-management/200.global-configuration-items/2010.request-buffer-length.md) 的值，可能导致 SQL 中超过 `request_buffer_length` 的部分无法用于等值关系推导。

## 使用方法

该功能适用分区表，且不限制分区类型，无需配置，默认可用。和多分区列路由、默认值路由、生成列路由、分区函数路由、分区名路由、分区 hint 路由相互独立，一般互不影响。对于需要多个功能配合才能正确计算分区的特殊 SQL ，预期也能正确运行并计算结果。

### 示例

#### 示例一：普通 SQL 请求 + 等值关系推导路由

1. 执行如下命令创建分区表

   ```sql
   obclient[test]> create table t1_hash(
       -> c1 int,
       -> c2 int,
       -> c3 int
       -> ) partition by hash (c1) partitions 4;
   ```

2. 执行 EXPLAIN ROUTE 命令查看普通 SQL 请求中存在等值关系推导时的路由选取过程

   ```sql
   obclient[test]> explain route select * from t1_hash where c1 = c2 and c2 = c3 and c3 = 1\G
   ```

#### 示例二：生成列 + 等值关系推导路由

1. 执行如下命令创建分区表

   ```sql
   obclient[test]> create table gen3(
       ->   c1 int,
       ->   c2 VARCHAR(20),
       ->   c3 VARCHAR(20),
       ->   c4 VARCHAR(20) GENERATED ALWAYS AS (substr(c3, 2)) VIRTUAL
       -> ) partition by list columns(c4, c1) (
       -> partition p0 values in (('ab',1), ('ab',2)),
       -> partition p1 values in (('cd',1), ('cd',2), ('cd',null)),
   ```

   ```sql
       -> (
   ```

#### 示例五：多表 Join + 等值关系推导路由

1. 执行如下命令创建分区表

   ```sql

   obclient[test]> create table if not exists tsh1 (c1 int,c2 varchar(10),c3 int) partition by hash(c1) partitions 4;

   obclient[test]> create table if not exists tsh2 (c1 int,c2 varchar(10),c3 int) partition by hash(c1) partitions 4;
   ```
