# OceanBase 数据库代理企业版 V4.3.1

## V4.3.1

### 版本信息

* 发布时间：2024 年 07 月 01 日

* 版本号：V4.3.1

* RPM 版本号：obproxy-4.3.1.0-402024062810

## 版本定位

ODP V4.3.1 是 ODP 4.3.x 系列的长期支持版本（LTS），推荐云上、线下业务用于 POC 测试、生产。SQL 代理新增主备库自动路由、指定多个 Zone 路由、ASCII 字符集路由、utf8mb4_0900_ai_ci 字符序路由等路由功能，新增 binlog_service_ip 支持域名及多地址功能，同时针对单机部署场景，优化路由策略，大幅提升性能。RPC 代理新增 HBase Empty Family 功能，完善 ObTableLSOps 请求类型，优化请求协议解析逻辑及路由信息批量获取的模式。

## 关键特性说明

### SQL 代理

#### 支持主备库自动路由

在 OceanBase 数据库 2.x/3.x 版本的主备库方案中，CLUSTER_NAME 对应一组主备集群，用户登录时默认主集群登陆，如果发生主备切换，ODP 能自动路由到新的主集群，CLUSTER_NAME 不变，不需要业务修改登录连接串。在 OceanBase 数据库 4.x 版本中，为了充分利用 OceanBase 数据库多租户的特性，改为按照租户粒度提供物理备库能力，即主或备的角色信息是属于租户的，而不是集群级别，两个不同租户可能互为主备关系，同时租户的主备关系不在数据库中进行记录，需要通过外部组件（OCP）进行维护。

主备库切换后，需要业务修改连接串的租户名信息，才能正常登录，对业务有影响。所以在 ODP 4.3.1 版本开始，ODP 通过和 OCP 接口交互，内部记录租户级主备关系，关联不同的租户，再通过 service_name 连接串管理，屏蔽用户对租户级别的主备感知，实现跟 OceanBase 数据库 2.x/3.x 版本同样效果的主备库自动路由功能。

主备库自动路由的详细介绍可参见 [主备租户自动路由](../../../600.data-routing/450.primary-and-backup-tenant-routing.md)。

#### 指定多个 Zone 路由

ODP 的配置项 `proxy_primary_zone_name` 支持指定单个 Zone 路由，将 ODP 收到的所有请求都路由到指定的 Zone。OceanBase 数据库支持 OLAP、OLTP 混合负载的场景，需要 ODP 能够将分析型请求路由到 OLAP 的多个副本，做到负载均衡。因此，ODP V4.3.1 扩展了 `proxy_primary_zone_name` 指定多 Zone 路由能力。

#### 字符集/字符序扩展

OceanBase 数据库 4.2.4 版本支持了 ASCII 字符集、TIS620 字符集、utf8mb4_0900_ai_ci 字符序，相应的，ODP V4.3.1 也对这些字符集/字符序做了路由支持。

#### binlog_service_ip 支持域名及多地址

在 Binlog 服务和 ODP 的交互架构中，ODP 每次发送 Binlog 相关 SQL 请求或者 Binlog Dump 请求，都会先通过 binlog_service_ip 获取相应的 Binlog 服务集群地址，然后再发送请求到具体的 Binlog 服务集群。目前对于 binlog_service_ip 仅支持填写一个 IP 地址且不支持域名，功能简单，不能满足部分高可用场景的需求。ODP V4.3.1 支持了域名及多地址功能，实现了以下场景的高可用：

* 负载均衡（LB）地址在不同可用区的物理 IP 不一样

* LB 切换时，具备自动恢复能力

#### 单机部署模式性能优化

目前云上独占/共享部署形态下 ODP 与 OceanBase 数据库主副本机器资源配比为 1:1，占用资源过多，需要提升 ODP 性能来减少资源占用，从而降低云上成本。

ODP 是 OceanBase 数据库专用的服务代理，其核心目标是解决分布式集群多节点路由问题，路由策略在分布式场景下非常有优势，但在单机场景，路由需求简单，复杂的路由逻辑变得没有必要。因此，在 ODP 4.3.1 版本，针对单机场景，优化了路由逻辑，同时增加一些系统编译等的优化。整体上，在线下 Sysbench 压测场景下，ODP V4.3.1 相对 V4.3.0 性能约有 30%-50% 的提升，优化效果明显。

### RPC 代理

#### ObTableLSOps 请求功能完善

ODP V4.3.0 设计了一种新的单操作格式以及相应的批量格式，来承载 checkAndInsUp 的语义，支持 ObTableLSOps 请求。ODP V4.3.1 进一步完善，支持了 LSOP 带多种 TableOperation，依据 log stream 划分子请求功能，同时优化了性能。

#### HBase Empty Family

当前 OceanBase 数据库的 Hbase API 只支持单列簇，为了更好的支持多列簇，以及一些情况下不用修改客户代码兼容，比如客户端 scan 传入空列簇情况，在 HBASE 模式中，引入 table group 的概念，默认 HBASE 的 table 对应 OceanBase 数据库的 table group，HBASE 的 column family 对应 OceanBase 数据库的 table，使用这种方式来兼容 HBASE 列簇的概念。这种情况下，Client 发送到 ODP 的请求里，table name 的值对应了当前的 table group name，ODP 层需要支持这种 table group 路由，从而支持新的 HBASE 模式。

## 兼容性变更

### 配置项变更

|              配置项               | 变更类型 |                                                                        变更说明                                                                        |
| --------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| enable_single_leader_node_routing | 新增     | 用于控制当租户为单节点 Primary Zone 部署形态时，是否使用更高效的路由规则。                                                                                  |
| rpc_max_response_batch_size       | 新增   | 用于设置单次发送回包中最大的 batch 数量。  |
| rpc_max_request_batch_size        | 变更  | 该配置项自 4.3.1 版本起默认值由 `5`  更新为  `20`。  |
| enable_standby                    | 变更     | 该配置项自 4.3.1 版本起支持控制是否开启主备租户路由能力。                                                                                 |
| proxy_primary_zone_name           | 变更     | 该配置项自 4.3.1 版本起支持配置多个 Zone 名称。 |
| binlog_service_ip                 | 变更    | 该配置项自 4.3.1 版本起支持配置多个 IP 地址或域名。   |

## 支持的 OceanBase 数据库版本

支持 OceanBase 数据库 4.x 和 3.x 以及更低版本。根据使用的 OceanBase 数据库版本不同，对应推荐如下：

* 当 OceanBase 数据库为 3.x 版本及更低版本时，建议使用 ODP V3.2.11。

* 当 OceanBase 数据库为 4.x 版本时，推荐使用 ODP V4.3.1（LTS 版本）。

## 缺陷修复

* 修复 ODP 连接集群，PS 二合一协议下，JDBC 执行 begin 语句夯住的问题。

* 修复主备库场景，第一次访问备集群失败后，再次访问持续报错失败的问题。
