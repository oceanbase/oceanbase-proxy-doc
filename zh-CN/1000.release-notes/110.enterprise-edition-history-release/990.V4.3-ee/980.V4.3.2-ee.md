# OceanBase 数据库代理企业版 V4.3.2

## V4.3.2

### 版本信息

* 发布时间：2024 年 10 月 08 日

* 版本号：V4.3.2

* RPM 版本号：obproxy-4.3.2.0-432024100811

## 版本定位

ODP 4.3.2 是 ODP 4.3.x 的最新版本，推荐云上、线下业务用于 POC 测试、生产。SQL 代理，新增基于权重的负载均衡和指定副本类型路由功能，丰富了弱读请求路由策略；新增 SQL 防火墙、GCP 上支持一段式连接等功能，提升云上竞争力；新增列存副本路由，配合 OceanBase 数据库 V4.3.3 完成 OLAP 业务对列存副本的需求；支持 MySQL 模式下 double 类型路由、非法日期类型路由，进一步完善路由功能；通过关闭单机模式下分布式事务路由功能、优化日志打印、优化 ODP CPU 消耗等多种方式，进一步优化产品性能；RPC 代理，适配了 getPartition 接口，支持客户端从 ODP 获取指定表的所有分区路由信息并缓存；隔离了处理跨分区子请求的线程和正常的工作线程，降低跨分区请求对正常单分区请求的 RT 影响，优化产品性能。

## 关键特性说明

### SQL 代理

#### 基于权重的负载均衡

目前，ODP 对弱读请求的路由有两种策略，一种是 LDC 路由，一种是按照 `proxy_route_policy` 配置的路由策略随机路由，能够满足大部分场景下用户对弱读请求的路由需求。云上推出只读副本、只读列存副本等副本类型后，用户对弱读请求提出更灵活的流量负载需求，为了满足新需求，同时也为了提升 ODP 代理的竞争力，新支持了基于权重的负载均衡策略。在 `proxy_route_policy` 中新增了 `WEAKREAD_WEIGHT_LOAD_BALANCE` 这一策略，用户可以为每个 Zone 配置 0～100 的权重值，ODP 按照副本的权重，转发弱读请求，最终达到用户期望的弱读流量负载均衡效果。

#### 弱读指定副本类型路由

OceanBase 数据库 4.3.3 版本新增一种副本类型——列存副本，用来加速 OLAP 请求的查询性能，列存副本的应用强依赖 ODP 的路由能力。部署架构上，给列存副本部署独立的 ODP 代理，并设置 `proxy_primary_zone_name` 策略，控制发往此 ODP 的请求只路由到指定的列存副本，从架构上隔离 OLAP 和 OLTP 请求；路由策略上，对发往列存副本的弱读请求，新增指定副本类型路由的策略：`proxy_route_policy` 新增路由策略 `TARGET_REPLICA_TYPE_WITH_LEADER`、`TARGET_REPLICA_TYPE_FOLLOWER_FIRST`、`TARGET_REPLICA_TYPE_FOLLOWER_ONLY`，同时新增 VIP 级别配置项 `route_target_replica_type` 指定路由的目标副本。

指定副本类型路由的策略，不仅适用于列存副本，同时适用于 FULL（全功能型副本）、READONLY（只读型副本）副本的路由。从产品层面考虑，整体设计为对所有副本通用的路由策略。通过配置不同的副本类型路由策略，可以支持读写分离、容灾策略、双主地址等更加丰富的业务场景。

#### SQL防火墙

ODP 1.9.x 版本，已经支持了 SQL 限流和熔断功能，但是使用流程较为复杂，不易规模化推广。ODP V4.3.2 对 SQL 防火墙功能进行修改、完善，支持多级别配置的设置、查看、删除，提升易用性和稳定性。目前，支持的拦截规则：

* 特定类型的 SQL，SELECT、INSERT、DELETE

* 无 where 条件的 SQL

* 使用了 like 子句的 SQL

* 自定义的 SQL

特别的，开启 SQL 防火墙功能后有 10% 以内的性能影响，实际业务场景需谨慎使用，按需开启。

#### 路由完善

OceanBase 数据库持续完善 MySQL 兼容性，新支持 double 类型作为分区键和 MySQL 非法日期类型两项功能，ODP V4.3.2 做了相应的适配，支持对 double 类型作为分区键的表进行准确路由，支持 MySQL 非法日期类型准确路由功能。为了满足生态工具需求，此版本支持了静态变量 port、支持了带注释的 SHOW MASTER STATUS 语句转发到 Binlog service 功能。此外，ODP V4.3.2 还针对 `select last_trace_id()` 语句做了特殊路由，将其路由到上一个成功连接的 OBServer 节点，以获取上一条 SQL 的准确的 TRACE ID，协助定位 SQL 日志，提高问题排查的效率。

### RPC 代理

#### 暴露分区接口

OBKV 新增接口 getPartition，支持用户获得指定表特定分区或全部分区的相关信息，以更好地使用 obkv table api 单分区的原子性或提高 HBase 同步数据的性能。ODP V4.3.2 适配了此接口，在 ODP 连接模式下，Client 需要通过多个流程获取指定表的 tableEntry 信息，ODP 将获取到的整个 tableEntry 信息组装成一个 RPC 包返回给客户端并进行缓存，提供分区路由信息的同时，不影响性能。

#### 跨分区子请求处理隔离

目前，ODP 运行中，如果有大量跨分区的请求，会导致其他正常的单分区请求 RT 上升，而用户对正常单分区请求的 RT 增长容忍度会比跨分区请求低，需要对此场景进行优化，将处理跨分区子请求的线程和执行单分区请求的工作线程隔离开，减少跨分区请求对单分区请求的 RT 影响。

## 兼容性变更

### 配置项变更

| 配置项 | 变更类型 | 变更说明 |
|-------|-------|--------|
| proxy_route_policy | 变更 | 该配置项自 4.3.2 版本起，取值范围中新增基于权重负载均衡的路由策略（`WEAKREAD_WEIGHT_LOAD_BALANCE`）和指定副本路由策略（`TARGET_REPLICA_TYPE_WITH_LEADER`/`TARGET_REPLICA_TYPE_FOLLOWER_FIRST`/`TARGET_REPLICA_TYPE_FOLLOWER_ONLY`）。 |
| route_target_replica_type | 新增 | 用于在弱读情况下指定副本类型，在 `proxy_route_policy` 配置为指定副本路由类型（`TARGET_REPLICA_TYPE_` 开头的路由策略）时，此配置才生效。 |
| weakread_weight_zone | 新增 | 用于配置各个 Zone 的权重，ODP会按照权重进行弱读请求的负载均衡。仅在 `proxy_route_policy` 指定为权重负载均衡路由策略（`WEAKREAD_WEIGHT_LOAD_BALANCE`）时生效。  |
| sql_firewall_config | 新增 | 设置 ODP 防火墙拦截规则。  |
| rpc_sub_request_isolation_mode | 新增 | 用于设置 RPC 子请求处理模式，以控制子请求的处理线程，减少其对正常请求 RT 的影响。 |
| rpc_async_task_thread_num  | 新增  | 用于设置 OBKV 异步线程的数量，旨在降低子请求转发以及大请求解析对普通请求的影响。 |
| rpc_sub_request_weight    | 新增  |用于设置 RPC 子请求的权重，子请求占用普通线程的数量随着权重的增高而增多。 |
| rpc_request_throttle_waiting_time | 新增  | 用于设置 RPC 请求限流等待时间。  |
| rpc_throttle_limit_qps_qa    | 新增  | 用于设置触发限流时 RPC 请求的 QPS 限制。  |
| rpc_throttle_trigger_percentage | 新增  | 用于设置限流触发阈值，当 RPC 请求占用内存达到设置的百分比后开始限流。  |
| enable_rpc_throttle   | 新增 | 用于控制是否基于 RPC 请求占用内存的情况进行流量控制。  |

## 支持的 OceanBase 数据库版本

支持 OceanBase 数据库 4.x 和 3.x 以及更低版本。根据使用的 OceanBase 数据库版本不同，对应推荐如下：

* 当 OceanBase 数据库为 3.x 版本及更低版本时，建议使用 ODP V3.2.11。

* 当 OceanBase 数据库为 4.x 版本时，推荐使用 ODP V4.3.1（LTS 版本）。

ODP V4.3.2 支持多项新功能，如果用户环境依赖新功能，推荐使用最新版本 V4.3.2；若不依赖新功能，推荐使用 LTS 版本 V4.3.1。

## 缺陷修复

* 修复租户设置大小写敏感，ODP 获取 Location 信息失败导致路由不准的问题。

* 修复租户指定 `lower_case_table_names = 0`，数据库名称使用大小写组合时，遇到 SYNC_DATABASE_COMMON_ERROR 导致的断连问题。

* 修复内存超限场景下，内存分配失败导致的抛异常问题，增加异常处理逻辑。

* 修复租户删除重建后，客户端传入更改后的 tenant_id，HBASE ODP 模式一直重试的问题。
