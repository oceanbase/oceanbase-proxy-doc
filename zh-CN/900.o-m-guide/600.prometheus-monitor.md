# Prometheus 监控

ODP 除了提供日志系统外，还通过 Prometheus 端口对外提供可观测的监控数据，以便对接不同的监控平台。

## 相关配置

ODP 中可通过如下配置项实现 Prometheus 监控功能的管理和调整。

| 名称 | 描述 |
|----|-----|
| prometheus_listen_port | 用于设置 ODP Prometheus 监听端口，默认为 `2884` |
| prometheus_cost_ms_unit | 用于控制是否将 Prometheus 的计算单位转换为毫秒(ms)，默认单位为微秒（us），若将此开关设置为 `true`，监控数据的时间单位变为毫秒（ms） |
| prometheus_sync_interval | Prometheus 监控数据的刷新周期，默认为 1 min |
| enable_prometheus | 用于控制是否启用 Prometheus 监控，默认为 `true` |
| enable_extra_prometheus_metric | 用于控制是否启用其他监控项，默认为 `false`，建议测试时设置为 `true` |

在 Prometheus 的相关配置项配置正确后（除 `enable_extra_prometheus_metric` 外，其他使用默认值即可），启动 ODP，并通过该 ODP 连接 OceanBase 集群执行若干 SQL。使用 `curl "http://127.1:2884/metrics"` 命令可以查看 Prometheus 相关监控数据。

## 基本监控项

| 监控项    | 描述   | 主要标签  | 备注    |
|---------|----------|----|--------|
| odp_transaction_total | 记录当前执行过的事务数量，单调递增。 | cluster（集群）、tenant（租户）、schema（数据库） | 无 |
| odp_sql_request_total | 记录当前执行过的 SQL 数量，单调递增。 | cluster（集群）、tenant（租户）、schema（数据库）、slowQuery（是否为慢查询）、sqlResult（执行结果）、sqlType（SQL 类型）、partitionHit（路由是否准确） | `sqlResult` 表示 SQL 执行结果，有两种返回值："fail"、"success"。ODP 自 4.3.0 版本起新增标签 `partitionHit`，表示路由是否准确，有两种返回值："true"、"false"。自 ODP 4.3.0 版本起，公有云上 odp_sql_request_total 监控项支持 `sqlType`，返回值如下：select、update、insert、delete、other。 |
| odp_current_session | 记录当前 ODP 存在的连接数量，包括客户端到 ODP 的连接数量、ODP 到 OBServer 节点的连接数量，非单调递增。 | cluster（集群）、tenant（租户）、schema（数据库）、sessionType（连接类型）、vip（客户端 VIP 地址） | `sessionType` 有两种返回值："client"、"server"，分别表示记录客户端和 ODP 之间、ODP 和 OBServer 节点之间存在的连接数量。ODP 自 4.3.0 版本起新增标签 `vip`，表示客户端 VIP 地址。<main id="notice" type='explain'><h4>说明</h4><p>本监控项不记录 proxyro@sys 用户的连接数量。</p></main> |
| odp_new_client_connections | 记录当前 ODP 所有登录过的客户端连接数量，单调递增。 | cluster（集群）、tenant（租户）、vip（客户端 VIP 地址）、ConnectionResult（是否登录成功） | 该监控项自 ODP 4.3.0 版本起新增。ODP 自 4.3.0 BP1 版本起新增 `ConnectionResult` 表示是否登录成功，有两种返回值："fail"、"success"。<main id="notice" type='explain'><h4>说明</h4><p>本监控项不记录 proxyro@sys 用户的连接数量。</p></main> |
| odp_sql_cost_total | 记录当前 SQL 执行所消耗的时间，单调递增。 | cluster（集群）、tenant（租户）、schema（数据库）、timeType（时间类型）、sqlType（SQL 类型） | `timeType` 有如下三种返回值：<ul><li>"prepare"：SQL 在 ODP 侧直到发送给 OBServer 节点为止的处理时间。</li><li>"server"：SQL 在 OBServer 节点侧的处理时间。</li><li>"total"：SQL 从 ODP 开始接收直到响应完成的时间。</li></ul>自 ODP 4.3.0 BP1 版本起，公有云上 odp_sql_cost_total 监控项支持 `sqlType`，返回值如下：select、update、insert、delete、other。 |
| odp_memory | 记录 ODP 当前内存信息。 | memType（内存类型） | `memType` 有两种返回值：<ul><li>HOLD：表示 ODP 向操作系统申请的内存值，分为两个部分，一部分是实际使用的内存，一部分是缓存的内存。</li><li>USED：表示 ODP 实际使用的内存。</li></ul> |

## 额外监控项

下表中的监控项默认无数据，在配置项 [enable_extra_prometheus_metric](../400.configuration-management/200.global-configuration-items/540.enable-extra-prometheus-metric.md) 被设置为 `true` 时才会提供数据。

| 监控项    | 描述   | 主要标签  | 备注    |
|---------|----------|----|--------|
| odp_request_byte | 记录客户端和 ODP 之间、ODP 和 OBServer 节点之间传输的字节数量，单调递增。 | cluster（集群）、tenant（租户）、schema（数据库）、sessionType（连接类型）、transType（数据类型） | `sessionType` 返回值中包含 "client" 和 "server"，分别表示记录客户端和 ODP 之间、ODP 和 OBServer 节点之间传输的字节数量。`transType` 返回值中包含 "request" 和 "response"，"request" 表示数据为请求数据，"response" 表示数据为响应数据。`sessionType` 和 `transType` 两两组合分别表示四种字节流。<main id="notice" type='explain'><h4>说明</h4><p>仅私有云环境存在该监控项，公有云环境无该监控项。</p></main> |
| odp_entry_total | 记录 ODP 查找路由信息 `table_entry`、`partition_entry` 相关的次数 | cluster（集群）、tenant（租户）、schema（数据库）、entryType（entry 类型）、routeHit（信息获取路线）、routeResult（信息获取结果） | `entryType` 存在如下三种返回值："table_entry"、"partition_info"、"partition_entry"。`routeHit` 存在 "true" 和 "false" 两种返回值，为 "true" 时表示信息是从本地缓存中获取。`routeResult` 存在 "true" 和 "false" 两种返回值，为 "true" 时表示信息获取成功，反之则表示获取失败。 |
