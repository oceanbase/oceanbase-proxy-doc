# SHOW PROXYPS

## 描述

该语句用于展示 prepare-statement（PS）协议使用场景中 PS 缓存信息。

## 权限要求

* 普通用户仅能查询属于同一用户的 PS 缓存信息。例如配置 `cs_id` 进行查询时，只有 `cs_id` 对应的客户端会话与当前用户属于同一用户时，查询才被允许执行。

* 对于 sys 租户和 `root@proxysys` 用户，可查看任意用户的 PS 缓存信息。
<!-- proxyro@sys 用户执行报错：ERROR 1064 (42000): You have an error in your SQL syntax; check the manual that corresponds to your OceanBase version for the right syntax to use near 'PROXYPS' at line 1 -->
## 语法

```sql
SHOW PROXYPS [cs_id] [like "sql"] [tenant like "tenant_name"] [DETAIL]
```

## 参数解释

| 参数  | 描述  |
|-------|------|
| SHOW PROXYPS | 展示全部 PS 缓存信息。 |
| cs_id  | 可选项，通过 cs_id 查询 PS 缓存信息。cs_id 为 ODP 内标记每个 Client Session 的 ID 号，可以通过 `SHOW PROCESSLIST;` 或者 `SHOW PROXYSESSION;` 命令查询，输出中的 `Id` 即为 cs_id。     |
| like "sql"  | 可选项，通过 SQL 查询 PS 缓存信息。支持配置 `_` 模糊查找单个字符、`%` 模糊查找多个字符。  |
| tenant like "tenant_name" | 可选项，通过租户名查询 PS 缓存信息。支持配置 `_` 模糊查找单个字符、`%` 模糊查找多个字符。  |
| DETAIL  | 可选项，控制是否显示 PS 语句的 SQL 和解析结果。 |

## 示例

* 指定 `cd_id` 和 SQL 查询
  
  ```sql
  SHOW PROXYPS 1 like '%select%';
  ```

  输出如下：

  ```shell
  +-------+--------------+-------------+-------+---------+-------------+--------------+-----------+--------------+
  | cs_id | cluster_name | tanant_name | ps_id | ps_name | prepare_sql | parse_result | used_mem  | used_session |
  +-------+--------------+-------------+-------+---------+-------------+--------------+-----------+--------------+
  | 1     | obcluster    | mysql       |  -1   | PS1     | NULL        | NULL         | 10533     |  1           |
  +-------+--------------+-------------+-------+---------+-------------+--------------+-----------+--------------+
  ```

* 执行 SQL 和租户查询
  
  ```shell
  SHOW PROXYPS like '%select%' tenant like '%mysql%';
  ```

  输出如下：

  ```shell
  +-------+--------------+-------------+-------+---------+-------------+--------------+-----------+--------------+
  | cs_id | cluster_name | tanant_name | ps_id | ps_name | prepare_sql | parse_result | used_mem  | used_session |
  +-------+--------------+-------------+-------+---------+-------------+--------------+-----------+--------------+
  | -1    | obcluster    | mysql       |  -1   | PS1     | NULL        | NULL         | 10533     |  1           |
  +-------+--------------+-------------+-------+---------+-------------+--------------+-----------+--------------+
  ```
  <!-- 输出的同一条信息，为啥一个 cs_id 是 1 一个是 -1 -->

### 字段介绍
<!-- 没有实际值的情况下，cs_id 列输出的是什么 -->
| 列名  | 含义  |
|-------|-------|
| cs_id | PS 缓存对应的客户端会话 ID。只有当 `SHOW PROXYPS` 命令指定了 `cs_id` 或者租户名才存在实际值，否则输出 `-1`。 |
| cluster_name | PS 缓存对应的集群名，只有当 `SHOW PROXYPS` 命令指定了 `cs_id` 或者租户名才存在实际值。 |
| tenant_name | PS 缓存对应的租户名，只有当 `SHOW PROXYPS` 命令指定了 `cs_id` 或者租户名才存在实际值。 |
| ps_id | PS 缓存对应的 PS ID，只有当 `SHOW PROXYPS` 命令指定了 `cs_id` 或者租户名，并且是二进制协议的 PS 语句才有这个字段值。 |
| ps_name | PS 缓存对应的 ps name，只有当 `SHOW PROXYPS` 命令指定了 `cs_id` 或者租户名，并且是文本协议的 PS 语句才有这个字段值。 |
| prepare_sql | PS 缓存对应的 PS SQL，当 `SHOW PROXYPS` 存在 `detail` 字段时有这个字段值。 |
| parse_result | PS 缓存对应的 PS SQL 解析结果，当 `SHOW PROXYPS` 存在 `detail` 字段时有这个字段值。 |
| used_mem | PS 缓存使用的内存值。 |
| used_session | PS 缓存被同时使用的 Session 数量。 |
