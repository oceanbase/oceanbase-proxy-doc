# Deploy ODP by using obd

This topic describes how to deploy ODP by using obd. The steps are as follows:

1. Check the installation environment.

2. Choose the appropriate version.

3. Install ODP by using obd.

4. Check the installation.

You can also deploy ODP in the following ways:

* To install ODP in OCP, see [Deploy ODP by using OCP](80.install-by-ocp.md).

* To install ODP by using the CLI, see [Deploy ODP by using the CLI](100.install-odp.md).

## Prerequisites

* CPU: After ODP is started, the CPU usage is about 0.7 C.

* Memory: After ODP is started, the memory usage is about 100 M.

* Disk space: The disk space is not specified. The disk space is determined based on the data size. We recommend that you use a disk of 10 GB or larger.

* OceanBase cluster: You need to prepare at least one OceanBase cluster. For more information, see [Deploy a database](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002012734) in the **OceanBase Database Document**.

* obd: You need to install obd. We recommend that you install the latest version. For more information, see [Install obd](https://www.oceanbase.com/docs/common-obd-cn-1000000003415274) in the **OceanBase Installation and Deployment Tool** document.

* (Optional) obconfigserver: If you have deployed obconfigserver, you can configure the `obproxy_config_server_url` parameter to start ODP. In this case, ODP can proxy all clusters registered with obconfigserver.

## Choose the appropriate version

If you are just learning how to use ODP, you can install the latest version. For production environments, we recommend that you pay attention to the feature updates and bug fixes for each version.

The ODP code is open source. You can find the OBProxy project in the OceanBase open-source project. For more information about each version, click [Releases](https://github.com/oceanbase/obproxy/releases). Each ODP version has been tested for functionality, stress, and performance, so you can use it with confidence.

You can deploy ODP in the following two ways:

* Add ODP to an existing OceanBase cluster by using the `obd cluster component add` command.

  In this method, the information of the existing OceanBase cluster is automatically obtained, and you do not need to configure parameters such as `rs_list` and `observer_sys_password`. After deployment, obd manages ODP based on the deployment name of the OceanBase cluster.

* Deploy ODP by using the `obd cluster deploy` command.

  In this method, you need to manually configure the information of the OceanBase cluster to be connected to. After deployment, obd manages ODP based on the deployment name set during deployment.

### Step 1: Modify the configuration file

Run the following command to create a configuration file:

```shell
vim add_odp.yaml
```

The content is as follows. Here is an example of deploying the Community Edition of ODP. If you plan to deploy the Enterprise Edition, you need to change `obproxy-ce` to `obproxy` in the configuration file.

```yaml
obproxy-ce:
  version: 4.3.0.0
  servers:
    - 10.10.10.1
  global:
    listen_port: 2883 # External port. The default value is 2883.
    prometheus_listen_port: 2884 # The Prometheus port. The default value is 2884.
    rpc_listen_port: 2885
    enable_obproxy_rpc_service: true
    home_path: /home/admin/obproxy
    enable_cluster_checkout: false
    skip_proxy_sys_private_check: true
    enable_strict_kernel_release: false
    client_session_id_version: 2 #This parameter is used to specify whether to use the new logic to generate the client session ID. The parameter type is integer. The value range is [1, 2] and the default value is 2 (use the new logic).
    proxy_id: 5 #This parameter is used to set the ID for an ODP. The parameter type is integer. The default value is 0 and the value range is [0, 8191].
    obproxy_sys_password: ****** # obproxy sys user password, can be empty. When a depends exists, obd gets this value from the oceanbase-ce of the depends.
```


## Common issues

### Failed to start

For Linux systems, ODP checks the operating system version based on the `enable_strict_kernel_release` parameter. If the check fails, the startup fails. Key logs are as follows:

```bash
[2021-10-13 10:38:17.235062] WARN [PROXY] get_kernel_release_by_uname (ob_config_server_processor.cpp:1039) [2060][Y0-0] [lt=14] [dc=0] unknown uname release(uinfo.release="4.18.0-80.el8.x86_64", ret=-4016)
```

You can use the `uname` command to view the kernel information. Currently, only the el series and alios series are allowed to pass the check. The check strategy is relatively conservative, which may result in some false positives. If you encounter the above issue on other Linux systems, you can disable this parameter to resolve the issue.

### Failed to connect to OceanBase Database

ODP connects to OceanBase Database using the proxyro user. If the user does not exist or the password of the proxyro user does not match the value of the `observer_sys_password` parameter, the connection to OceanBase Database fails. The error message is as follows:

```bash
ERROR 2013 (HY000): Lost connection to MySQL server at 'reading authorization packet', system error: 11
```

In this case, you need to choose different solutions based on the specific situation:

1. The user does not exist

   You can use the `root@sys` user to directly connect to OceanBase Database and create the proxyro user in the sys tenant.

   ```sql
   create user proxyro identified by '*******';
   grant select on *.* to proxyro;
   ```

2. The password of the proxyro user does not match the value of the `observer_sys_password` parameter. In this case, you can choose one of the following solutions:

   1. You can use the `root@sys` user to directly connect to OceanBase Database and modify the password of the proxyro user to match the value of the `observer_sys_password` parameter set when ODP was started.

      ```bash
      ALTER USER proxyro IDENTIFIED BY 'password';
      ```

   2. You can log in to ODP as the `root@proxysys` user and modify the password of the `proxyro@sys` user. After the password is modified, you need to restart ODP.

      ```sql
      alter proxyconfig set observer_sys_password = 'password';
      ```

  <h4>Notice</h4>
  <p>In the preceding statements, <code>password</code> must be set to the original password, not the SHA1 value of the password. </p>
