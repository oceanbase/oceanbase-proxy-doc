# Date calculation functions

This topic describes how to use date calculation functions in OceanBase Database Proxy (ODP).

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <ul>
  <li><p>The current time used in the function is calculated based on the ODP. The calculation results may differ from those of the OBServer node. In scenarios where hash partitioning is used and the current time is involved in the calculation, accurate routing may not be possible.</p></li>
  <li><p>Since ODP V4.3.3, routing parsing is supported for partitioning keys defined in the TIMESTAMP format.</p></li>
  </ul>
</main>

## Oracle/MySQL functions

The date-related functions in MySQL include CURDATE/CURRENT_DATE, CURTIME/CURRENT_TIME, and CURRENT_TIMESTAMP/NOW.

The date-related functions in Oracle include CURRENT_DATE, CURRENT_TIMESTAMP, SYSTIMESTAMP, and SYSDATE.

<main id="notice" type='explain'>
   <h4>Note</h4>
   <ul>
   <li>
   <p>Do not add parentheses to the end of an Oracle function, but you can add parentheses to the end of a MySQL function. </p>
   </li>
   <li>
   <p>In Oracle mode, the <code>CURRENT_TIMESTAMP(precision)</code> syntax is not supported. </p>
   </li>
   </ul>
</main>

Assume that the database contains a table named `t1` and that the `c1` column is the partitioning key. ODP can accurately route an SQL request to select all rows where the value of the `c1` column is equal to the current system date in the `YYYY/MM/DD` format from the `t1` table. Example:

```shell
select * from t1 where c1=to_char(sysdate,'YYYY/MM/DD');
```

## MONTH

The MONTH function extracts the month from a given date and supports only the MONTH(date) syntax.

* Example 1: Use in a partitioning expression

  Create an `orders` table and specify partitioning by month.

  ```sql
  CREATE TABLE orders (
      order_id INT,
      order_date DATE,
      amount DECIMAL(10,2)
  )
  PARTITION BY RANGE (MONTH(order_date)) (
      PARTITION p1 VALUES LESS THAN (2),   -- January
      PARTITION p2 VALUES LESS THAN (3),   -- February
      PARTITION p3 VALUES LESS THAN (4),   -- March
      ...
      PARTITION p12 VALUES LESS THAN (13)  -- December
  );
  ```

* Example 2: Use in the partitioning key

  Assume that the database contains a table named `t1` and that the `c1` column is the partitioning key. ODP can accurately route an SQL request to select all rows where the value of the `c1` column is equal to the month of the date `2025-05-20` from the `t1` table.

  ```shell
  select * from t1 where c1=MONTH('2025-05-20');
  ```

## TO_DATE

The TO_DATE function converts a string to a date or datetime type. It supports only the to_date(char,[fmt]) syntax:

* `char` specifies the string to be converted, which represents a specific date and time.

* `fmt` is an optional parameter that specifies the conversion format.

Assume that the database contains a table named `t1` and that the `c1` column is the partitioning key. ODP can accurately route an SQL request to select all rows where the value of the `c1` column is equal to the datetime converted from the string `20230823024916` in the specified format from the `t1` table. Example:

```shell
select * from t1 where c1=TO_DATE('20230823024916','YYYYMMDDHH24MISS');
```

## TO_DAYS

The TO_DAYS function converts a given date into an integer representing the number of days since the start of the year 0.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The number of days returned by this function is the number of days from <code>0000-01-01</code>. </p>
</main>

ODP supports TO_DAYS in the partitioning key. ODP converts it into the corresponding number of days to accurately route the SQL statement.

Assume that the database contains a table named `t1`, where `c1` is the partitioning key. Query all rows in the `t1` table where the values in the `c1` column are equal to the number of days from `0000-01-01` to `2015-11-04`. Example:

```shell
select * from t1 where c1=TO_DAYS('2015-11-04');
```

## TO_TIMESTAMP

The TO_TIMESTAMP function converts a string into a timestamp. At present, only the to_timestamp(str, [fmt]) syntax is supported:

* `str` is the string to be converted, which represents a specific date and time.

* `fmt` is an optional parameter that specifies the conversion format.

Assume that the database contains a table named `t1`, where `c1` is the partitioning key. Query all rows in the `t1` table where the values in the `c1` column are equal to the timestamp generated by converting the string `20230823191416` into the specified format. ODP can accurately route the SQL statement. Example:

```shell
select * from t1 where c1=to_timestamp('20230823191416','YYYY-MM-DD HH24:MI:SSXFF');
```
