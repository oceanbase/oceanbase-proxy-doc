# Session Connection Pool

## Background information

ODP supports the session-level connection pool feature since V4.3.5. This feature is intended to address the issue where frequent new connections are established between the business and ODP in short connection scenarios, leading to high costs due to frequent connections between ODP and multiple OBServer nodes, and to improve the concurrency performance in short connection scenarios.

## Considerations

A session connection pool is unavailable in the following cases:

* The client uses a service name. For more information about service names, see [Automatic routing and read/write splitting for primary and standby tenants](../600.data-routing/450.primary-and-backup-tenant-routing.md).

* The ODP parameter `server_protocol` is set to `compressed mysql`. You can run the `show proxyconfig like 'server_protocol';` command to view the value of the `server_protocol` parameter.

* The client is an Oracle tenant.

* The client has enabled distributed transactions.

* The OceanBase 2.0 protocol is used between the client and ODP.

* SSL is enabled on the client.

* The client requests a binlog.

## Limitations

To use this feature, make sure that the ODP version is V4.3.5 or later, and the OceanBase Database version is V4.4.0 or later.

## Use

### Configuration parameters

You can modify the [connection_pool_mode](../400.configuration-management/200.global-configuration-items/253.connection_pool_mode.md) parameter to enable or disable the session connection pool. For example, execute the following statement to enable the connection pool:

```sql
obclient> alter proxyconfig set connection_pool_mode='session';
```

ODP also provides the following parameters to control the session connection pool. We recommend that you use the default values:

| Parameter  | Default value  | Description  |
|-----|-----|-----|
| [session_pool_idle_timeout](../400.configuration-management/200.global-configuration-items/2200.session_pool_idle_timeout.md) | 5m | The maximum time that a session can be retained after it is returned to the connection pool.   |
| [session_pool_reset_interval](../400.configuration-management/200.global-configuration-items/2203.session_pool_reset_interval.md) | 10m | The time interval for sending `COM_RESET_CONNECTION` to sessions in the connection pool that have not been reset.  |
| [session_pool_stat_log_interval](../400.configuration-management/200.global-configuration-items/2205.session_pool_stat_log_interval.md) | 1m | The time interval for session connection pool statistics logs.   |

### O&M commands

* View session information

  Log in to the `sys` tenant of the cluster as the `root` user and run the `SHOW GLOBALSESSION` command to view the session information in the session pool. Here is an example of viewing the session information of a specified tenant. For more information, see [SHOW GLOBALSESSION](../660.odp-command/20.odp-proprietary-commands/400.show/900.show-globalsession.md).

  Log in to the `sys` tenant of the cluster as the `root` user:

  ```shell
  [admin@obtest ~]$ obclient -uroot@sys#obcluster -h10.10.10.1 -P2883 -p
  ```

  View session information:

  ```sql
  SHOW GLOBALSESSION ATTRIBUTE 'obcluster:test'\G
  ```

  The output is as follows:


* Terminate a session

  Log in to the `sys` tenant of the cluster as the `root` user and run the `KILL GLOBALSESSION` command to terminate a session in the session pool. Here is an example of terminating a specified session. For more information, see [KILL GLOBALSESSION](../660.odp-command/20.odp-proprietary-commands/200.kill/100.kill-globalsession.md).

  Log in to the `sys` tenant of the cluster as the `root` user:

  ```shell
  [admin@obtest ~]$ obclient -uroot@sys#obcluster -h10.10.10.1 -P2883 -p
  ```

  Terminate a session:

  ```sql
   KILL GLOBALSESSION 'obcluster:test' 193;
   ```

   In the example, `193` is the value of `ss_id` in the output of the `SHOW GLOBALSESSION` command. You can replace it with the actual value.
