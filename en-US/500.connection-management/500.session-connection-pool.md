# Session connection pool

## Overview

Starting with ODP V4.3.5, a session-level connection pool reduces the cost of frequent new client connections to ODP and frequent ODP-to-OBServer connections in short-connection workloads, improving concurrency.

## Restrictions

The session connection pool is not available if any of the following applies:

* The client uses a service name. For details, see [Automatic routing to the primary/standby tenants](../600.data-routing/450.primary-and-backup-tenant-routing.md).

* ODP `server_protocol` is `compressed mysql`. Run `show proxyconfig like 'server_protocol';` to check.

* The client uses an Oracle tenant.

* The client has used distributed transactions.

* The client uses OceanBase 2.0 protocol between client and ODP.

* The client uses SSL.

* The request is a BINLOG request.

## Version requirements

ODP V4.3.5 or later and OceanBase Database V4.4.0 or later.

## Usage

### Parameters

Enable the pool by modifying the [connection_pool_mode](../400.configuration-management/200.global-configuration-items/253.connection_pool_mode.md) parameter, for example:

```sql
obclient> alter proxyconfig set connection_pool_mode='session';
```

The following parameters tune the pool; defaults are recommended:

| Parameter | Default | Description |
|-----|-----|-----|
| [session_pool_idle_timeout](../400.configuration-management/200.global-configuration-items/2200.session_pool_idle_timeout.md) | 5m | Maximum time a returned session may stay idle in the pool. |
| [session_pool_reset_interval](../400.configuration-management/200.global-configuration-items/2203.session_pool_reset_interval.md) | 10m | Interval for sending `COM_RESET_CONNECTION` to sessions in the pool that have not been reset. |
| [session_pool_stat_log_interval](../400.configuration-management/200.global-configuration-items/2205.session_pool_stat_log_interval.md) | 1m | Interval for session pool statistics logs. |

### Administration commands

* View sessions

  Log in to the cluster `sys` tenant as `root` and run `SHOW GLOBALSESSION`. To view a tenant’s sessions, see [SHOW GLOBALSESSION](../660.odp-command/20.odp-proprietary-commands/400.show/900.show-globalsession.md).

  ```shell
  [admin@obtest ~]$ obclient -uroot@sys#obcluster -h10.10.10.1 -P2883 -p
  ```

  ```sql
  SHOW GLOBALSESSION ATTRIBUTE 'obcluster:test'\G
  ```

  Example output:

* Terminate sessions

  As `root` on `sys`, run `KILL GLOBALSESSION`. See [KILL GLOBALSESSION](../660.odp-command/20.odp-proprietary-commands/200.kill/100.kill-globalsession.md).

  ```shell
  [admin@obtest ~]$ obclient -uroot@sys#obcluster -h10.10.10.1 -P2883 -p
  ```

  ```sql
   KILL GLOBALSESSION 'obcluster:test' 193;
  ```

  Replace `193` with the `ss_id` from `SHOW GLOBALSESSION` output.
