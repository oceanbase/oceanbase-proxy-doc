# SHOW

## Description

This statement is used to display the information about ODP and OceanBase Database.

## Syntax

```sql
SHOW {
    PROXYINFO BINARY
   | PROXYINFO UPGRADE
   | PROXYINFO IDC
   | PROXYCLUSTER [IDC] [like 'cluster_name']
   | PROXYCONFIG [diff] [user] [like 'config_name']
   | PROXYCONGESTION [all] [cluster_name]
   | PROXYMEMORY [objpool] [num]
   | PROXYNET CONNECTION [thread_id [LIMIT xx]]
   | PROXYNET THREAD
   | PROXYROUTE [like 'cluster [tenant [db [table]]]']
   | PROXYROUTE GLOBALINDEX
   | PROXYROUTE PARTITION
   | PROXYROUTE QUERYASYNC
   | PROXYROUTE TABLEGROUP
   | PROXYROUTE TABLETLS [tablet_to_ls_num]
   | PROXYROUTE RPCCTX
   | PROXYRPC THREAD
   | PROXYRPC REQUESTSTAT [request_type]
   | PROXYSESSION
   | PROXYSESSION ATTRIBUTE [id [like 'xxx']]
   | PROXYSESSION STAT id [like 'xx']
   | PROXYSESSION VARIABLES [all] id [like 'xx']
   | PROXYSM [RPC] [sm_id]
   | PROXYSTAT [refresh] [like 'name']
   | WARNLOG [[[log_id], thread_id], time]
};
```

## Parameter description

| Parameter | Description |
|--------|--------|
| PROXYINFO BINARY | Displays the binary information of the ODP in rich text format, including the version, packaging time, and MD5 value. |
| PROXYINFO UPGRADE | Displays the running and upgrade information of the ODP in rich text format. |
| PROXYINFO IDC | Displays the IDC matching information of the ODP in rich text format. |
| PROXYCLUSTER [IDC] [like 'cluster_name'] | Displays the rs_list information of the cluster in rich text format. You can use the like option to perform fuzzy matching (supports % and _). For example, `show proxycluster like "%ob%";`. If you specify the IDC parameter, the idc_list information of the cluster is displayed. |
| PROXYCONFIG [diff] [user] [like 'config_name'] | Displays the configuration items of the ODP. If you specify the diff parameter, only the configuration items that are different from the default parameters are displayed. If you specify the diff user parameter, only the user-level configuration items that are different from the default parameters are displayed. You can use the like option to perform fuzzy matching (supports % and _). For example, `show proxyconfig diff user like "%cpu%";`. |
| PROXYCONGESTION [all] [cluster_name] | Displays the information of all clusters of the ODP. The following scenarios are supported based on the parameters specified:<ul><li>By default, the information of all clusters is displayed. The information is displayed only when the value of any of the following parameters is true: `dead_congested`, `alive_congested`, `is_zone_upgrading`, or `is_server_upgrading`. </li><li>If you specify the <code>all</code> parameter, the information of all clusters is displayed, including the information of the OBServe nodes in the blacklists and those not in the blacklists. </li><li>If you specify the <code>clustername</code> parameter, the information of the specified cluster is displayed. </li><li>If you specify all parameters, the information of the specified cluster is displayed. </li></ul><main id="notice" type='explain'><h4>Note</h4><p>If the ODP is of V1.1.2 or earlier, you do not need to enclose the <code>clustername</code> parameter in single or double quotation marks. If the ODP is of V1.1.2 or later, you must enclose the <code>clustername</code> parameter in single or double quotation marks. </p></main> |
| PROXYMEMORY [objpool] [num] | Displays the memory usage of the ODP, including the memory allocated to each module, the memory currently being used, and the module type. This information is used to analyze the performance of the ODP. After you specify a number (num) in the command, the memory allocation stack is displayed. At most 10 layers are displayed. To use this feature, you must modify the [mem_leak_check_mod_name](../../../400.configuration-management/200.global-configuration-items/1437.mem-leak-check-mod-name.md) and [mem_leak_check_class_name](../../../400.configuration-management/200.global-configuration-items/1435.mem-leak-check-class-name.md) parameters. |
| PROXYNET CONNECTION [thread_id [LIMIT xx]] | Displays the internal attribute status of all network connections on the ODP. You can specify the `thread_id` parameter to display the connection status of a specified thread. If you do not specify the `thread_id` parameter, the attribute status of all connections on the ODP is displayed. If you specify the `thread id` parameter, you can use `LIMIT [offset,] rows` and `LIMIT rows OFFSET offset`. The syntax is fully compatible with that of MySQL. If you set `rows` to -1, all rows are displayed.<main id="notice" type='explain'><h4>Note</h4><p>For more information, see <a href='../../../500.connection-management/450.net-session.md'>Network connections</a>. </p></main>  |
| PROXYNET THREAD | Displays the attribute status of each working thread of the ODP. The number of working threads of the ODP is controlled by the [work_thread_num](../../../400.configuration-management/200.global-configuration-items/2570.work_thread_num.md) parameter. |
| PROXYROUTE [like 'cluster [tenant [db [table]]]'] | Displays the table entry status of the ODP. By default, the status of all table entries is displayed. You can use the like option to perform fuzzy matching (supports % and _). For example, `show proxyroute like 'obcluster sy_ oceanba% ob_all_%';`. The SQL routing address information of the ODP is stored in table entries. Each table entry consists of the cluster name, tenant name, database name, and table name. If the SQL statement does not specify the table name, the `__all_dummy` table is used to mark the table entry. |
| PROXYROUTE GLOBALINDEX  | Displays the OBKV global index information of the ODP. The cache information can be controlled by the [partition_location_expire_relative_time](../../../400.configuration-management/200.global-configuration-items/1720.partition-location-expire-rela.md) parameter.  |
| PROXYROUTE PARTITION  | Displays the partition information of the ODP. The cache information can be controlled by the [partition_location_expire_relative_time](../../../400.configuration-management/200.global-configuration-items/1720.partition-location-expire-rela.md) parameter.   |
| PROXYROUTE QUERYASYNC  | Displays the OBKV asynchronous query information of the ODP. The cache information can be controlled by the [partition_location_expire_relative_time](../../../400.configuration-management/200.global-configuration-items/1720.partition-location-expire-rela.md) parameter.  |
| PROXYROUTE TABLEGROUP  | Displays the multi-column family request information of the ODP. The cache information can be controlled by the [partition_location_expire_relative_time](../../../400.configuration-management/200.global-configuration-items/1720.partition-location-expire-rela.md) parameter.  |
| PROXYROUTE TABLETLS [tablet_to_ls_num]  | Displays the ls_id information of the ODP. Currently, only the LSOp requests are supported. `tablet_to_ls_num` specifies the number of data to be displayed. The cache information can be controlled by the [partition_location_expire_relative_time](../../../400.configuration-management/200.global-configuration-items/1720.partition-location-expire-rela.md) parameter.  |
| PROXYROUTE RPCCTX  | Displays the information of the users who log in to the ODP through the RPC port. You can use this command to verify whether the ODP supports the distributed capabilities for the login users. You cannot clear the configuration items, and it is not recommended to clear the login information. Otherwise, the users may fail to log in.  |
| PROXYRPC THREAD  | Displays the request processing status of the current thread in the ODP.  |
| PROXYRPC REQUESTSTAT [request_type] | Displays the status of each request processed by different threads in the ODP. By default, the status of all requests is displayed. You can specify the `request_type` parameter to display the status of a specific type of request. Currently, you can specify the `request_type` parameter to `OB_TABLE_API_LOGIN`, `OB_TABLE_API_EXECUTE`, `OB_TABLE_API_BATCH_EXECUTE`, `OB_TABLE_API_EXECUTE_QUERY`, `OB_TABLE_API_QUERY_AND_MUTATE`, `OB_TABLE_API_EXECUTE_QUERY_SYNC`, `OB_TABLE_API_DIRECT_LOAD`, or `OB_TABLE_API_LS_EXECUTE`. If you specify other values, the status of all request types is displayed by default.<main id="notice" type='explain'><h4>Note</h4><p>This command is used for troubleshooting. If no corresponding request exists in the ODP when you execute this command, the output result is <code>0</code>. </p></main> |
| PROXYSESSION | Displays the internal status of all client sessions connected to the current ODP. Unlike the `SHOW PROCESSLIST` command, the `SHOW PROXYSESSION` command can also display the cluster to which each tenant belongs.  |
| PROXYSESSION ATTRIBUTE [id [like 'xxx']] | Displays the detailed internal status of the specified client session, including the related server sessions. For more information, see [Client connections](../../../500.connection-management/300.client-session.md).<ul><li>If you do not specify the <code>id</code> parameter, the detailed status of the current session is displayed (ODP 1.1.0 and later). You can also perform fuzzy query on the value of the specified attribute name in the current session (ODP 1.1.2 and later). </li><li>If you specify the <code>id</code> parameter, you can perform fuzzy query on the value of the specified attribute name. </li><li><code>id</code> can be <code>cs_id</code> or <code>connection_id</code>. The display result is the same. </br><code>cs_id</code> is the ID of each client in the ODP. <code>connection_id</code> is the ID of each client in the entire OceanBase Database. In MySQL mode, you can obtain <code>connection_id</code> by executing the <code>SELECT CONNECTION_ID();</code> statement. In Oracle mode, you can obtain <code>connection_id</code> by executing the <code>SHOW FULL PROCESSLIST;</code> statement. </li><li>You can use the like option to perform fuzzy matching, which supports % and _. </li></ul> |
| PROXYSESSION STAT id [like 'xx'] | Displays the internal statistics of the specified client session in the ODP, including the number of SQL requests and the size of SQL requests. For more information, see [Client connections](../../../500.connection-management/300.client-session.md).<ul><li><code>id</code> can be <code>cs_id</code> or <code>connection_id</code>. The display result is the same. </br><code>cs_id</code> is the ID of each client in the ODP. <code>connection_id</code> is the ID of each client in the entire OceanBase Database. In MySQL mode, you can obtain <code>connection_id</code> by executing the <code>SELECT CONNECTION_ID();</code> statement. In Oracle mode, you can obtain <code>connection_id</code> by executing the <code>SHOW FULL PROCESSLIST;</code> statement. </li><li>You can use the like option to perform fuzzy matching, which supports % and _. </li></ul>  |
| PROXYSESSION VARIABLES [all] id [like 'xx'] | Displays the session variables of the specified client session. For more information, see [Client connections](../../../500.connection-management/300.client-session.md).<ul><li>If you do not specify the <code>all</code> parameter, the local session variables of the specified client session are displayed, including the modified system variables and user variables. </li><li>If you specify the <code>all</code> parameter, all session variables of the specified client session are displayed, including all system variables and user variables. </li><li><code>id</code> can be <code>cs_id</code> or <code>connection_id</code>. The display result is the same. </br><code>cs_id</code> is the ID of each client in the ODP. <code>connection_id</code> is the ID of each client in the entire OceanBase Database. In MySQL mode, you can obtain <code>connection_id</code> by executing the <code>SELECT CONNECTION_ID();</code> statement. In Oracle mode, you can obtain <code>connection_id</code> by executing the <code>SHOW FULL PROCESSLIST;</code> statement. </li><li>You can use the like option to perform fuzzy matching, which supports % and _. </li></ul> |
| PROXYSM [sm_id] | Displays the internal status of each StateMachine of the ODP in rich text format. You can specify the `sm_id` parameter to display the internal status of the specified StateMachine. |
| PROXYSM RPC [sm_id] | Displays the status of the ObRpcRequestSMs that have not been released in the ODP. You can specify the `sm_id` parameter to display the status of the specified ObRpcRequestSM. An ObRpcRequestSM is released after it executes the request.<main id="notice" type='explain'><h4>Note</h4><p>You must set the <code>rpc_enable_requestsm_info</code> parameter to <code>True</code> to query the information. Otherwise, the query result is empty. </p></main>  |
| PROXYSTAT [refresh] [like 'xx'] | Displays the statistics of the ODP.<ul><li>If you do not specify the <code>refresh</code> parameter, the statistics of the ODP collected last time are displayed by default. </li><li>If you specify the <code>refresh</code> parameter, the local statistics are forcibly collected and then displayed. </li><li>You can use the like option to perform fuzzy matching, which supports % and _. </li><li>If the value of the <code>persist_type</code> statistic is <code>PERSISTENT</code>, the statistics are persisted to the <code>ob_all_proxy_stat</code> table of the remote database. </li><li>The local statistics update time is controlled by the <a href='../../../400.configuration-management/200.global-configuration-items/2470.stat-table-sync-interval.md'>stat_table_sync_interval</a> parameter. By default, the statistics are updated every 60 seconds. </li></ul> |
| WARNLOG [[[log_id], thread_id], time] | Displays the `WARN` and `ERROR` level alert logs of the ODP that are not earlier than the specified time and have the specified log ID. You can specify the `tread_id` parameter to query the alert logs of the corresponding thread. If you do not care about the log ID or thread ID when querying the logs, you can set `log_id` or `thread_id` to -1. In this case, the alert logs of all log IDs or thread IDs are queried. |
