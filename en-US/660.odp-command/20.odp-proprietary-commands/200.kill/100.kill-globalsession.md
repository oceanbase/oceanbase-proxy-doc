# KILL GLOBALSESSION

## Description

This statement is used to terminate a session in the session connection pool.

## Privilege requirements

This command can be executed only by the root@sys user or the root@proxysys user. The root@sys user can terminate all sessions of all tenants in the cluster. The root@proxysys user can terminate all sessions of all clusters and all tenants.

## Syntax

```sql
KILL GLOBALSESSION 'dbkey' [ss_id]
```

## Parameters

| Parameter  | Description  |
|-------|------|
| 'dbkey'  | specifies the tenant. The value is in the format of <code>cluster name:tenant name</code>. If you specify only `dbkey` in the command, all sessions of the specified tenant are terminated. You can run the `SHOW GLOBALSESSION` command to view the sessions in the session connection pool. For more information, see [SHOW GLOBALSESSION](../400.show/900.show-globalsession.md).     |
| ss_id  | the unique ID of the session identified by ODP. You can run the `SHOW GLOBALSESSION` command to view this ID. For more information, see [SHOW GLOBALSESSION](../400.show/900.show-globalsession.md). You can specify `ss_id` to terminate a session.  |

## Example

1. Log in to OceanBase Database by using the ODP of the root@sys user

   ```shell
   obclient -h10.10.10.1 -uroot@sys#obdemo -P2883 -p -c -A
   ```

   Note that this is just an example. You must modify the parameters based on your actual situation. For more information about how to connect to OceanBase Database, see [Connect to an OceanBase tenant by using OBClient (MySQL mode)](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002013251).
