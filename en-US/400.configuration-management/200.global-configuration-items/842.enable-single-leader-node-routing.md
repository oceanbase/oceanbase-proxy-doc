# enable_single_leader_node_routing

`enable_single_leader_node_routing` specifies whether to apply more efficient routing rules when a tenant is deployed in leader concentration mode where replicas of the tenant are distributed in the 1:1:1 (leader:follower:follower) pattern in the OceanBase cluster. If `enable_single_leader_node_routing` is set to `True` for a tenant deployed in leader concentration mode, OceanBase Database Proxy (ODP) uses more efficient routing rules to quickly route strong-consistency read requests to the leader when it forwards requests of this tenant. This can improve the routing and forwarding performance by 20% to 30%.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <ul><li>
  <p>This parameter was introduced in version 4.3.1 and the default value was updated to <code>False</code> in version 4.3.5 BP1. </p>
  </li><li>
  <p>In a single-leader mode, if this parameter is set to <code>True</code>, ODP will use the MySQL protocol instead of the OceanBase 2.0 protocol. If your ODP deployment relies on features or components of the OceanBase 2.0 protocol, set this parameter to <code>False</code>. </p>
  </li><li>
  <p>This parameter is not applicable when the OceanBase cluster is deployed as a single node. </p>
  </li></ul>
</main>

|  Attribute    | Description     |
|----------|---------|
| Parameter type |   Boolean      |
| Default value   | False    |
| Value range | <ul><li>True: Use more efficient routing rules. </li><li>False: Do not use more efficient routing rules. </li></ul>  |
| Effective only after ODP restart | No  |

Before you use this parameter, you must be aware of the following:

* When this parameter is set to `True`, ODP will automatically adjust the routing rules for tenants whose replica distribution meets the conditions. Tenants whose replica distribution does not meet the conditions will not be affected.

* When this parameter is set to `True` and the tenant meets the conditions, the following features will be unavailable. If you want to use these features, you must manually set this parameter to `False`.

  * Routing for distributed transactions

  * Routing for replication table balancing

  * Weak-read latency threshold
