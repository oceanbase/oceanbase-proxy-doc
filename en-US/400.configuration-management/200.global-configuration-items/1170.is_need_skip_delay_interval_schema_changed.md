# is_need_skip_delay_interval_schema_changed

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>ODP V4.3.1 BP4 and later V4.3.1.x versions, and V4.3.4 and later versions support this parameter. </p>
</main>

## Description

`is_need_skip_delay_interval_schema_changed` specifies whether to skip the delay interval when the schema version of a table changes.

This parameter is mainly used in the automatic splitting of range-partitioned tables. For example, if a table in OceanBase Database splits within 5 seconds between partitions, ODP will build new partition information and force the next partition information build to wait at least 5 seconds before triggering an update. This will prevent ODP from obtaining accurate partition routing information. We recommend that you set this parameter to `True`. When the partition schema version is less than the table schema version, the partition routing information will be refreshed directly without being affected by the interval.

## Parameter description

| Parameter | Description |
|----------|---------|
| Parameter type | Boolean |
| Default value | False |
| Value range | <ul><li>True: Skip the delay interval.</li><li>False: Do not skip the delay interval.</li></ul>  |
| Effective after ODP restart | No  |

## Example

Run the following command to skip the delay interval when the schema version of a table changes.

```shell
obclient> alter proxyconfig set is_need_skip_delay_interval_schema_changed='True';
```
