# is_need_skip_delay_interval_schema_changed

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter is supported starting from ODP V4.3.1 BP4 and later V4.3.1.x versions. </p>
</main>

## Description

`is_need_skip_delay_interval_schema_changed` specifies whether to skip the delay interval when the schema version of a table changes.

This parameter is mainly used in the automatic splitting of range partitions. For example, if a table in OceanBase Database splits within 5 seconds, ODP will force the next partition information build to wait at least 5 seconds before triggering an update, which will prevent ODP from obtaining accurate partition routing information. It is recommended to set this parameter to `True`. When the partition schema version is less than the table's schema version, the partition routing information will be refreshed directly without being affected by the delay interval.

## Attributes

|  Attribute    | Description     |
|----------|---------|
| Parameter type | Boolean |
| Default value   | False     |
| Value range | <ul><li>True: Skip the delay interval.</li><li>False: Do not skip the delay interval.</li></ul>  |
| Effective only after ODP restart | No  |

## Examples

Run the following command to skip the delay interval when the schema version of a table changes.

```shell
obclient> alter proxyconfig set is_need_skip_delay_interval_schema_changed='True';
```
