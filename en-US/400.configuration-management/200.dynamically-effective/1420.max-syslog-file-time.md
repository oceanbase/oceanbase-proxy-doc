# max_syslog_file_time

`max_syslog_file_time` specifies the maximum retention period of archive logs. The value `0` specifies to ignore this limitation.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter applies only when the <a href="./900.enable-syslog-file-compress.md">enable_syslog_file_compress</a> is set to <code>true</code>. </p>
</main>

|  Attribute    | Description     |
|----------|---------|
| Parameter type | Time      |
| Default value | 7d     |
| Value range | [1s, +∞) |
| Effective upon ODP restart | No |

This parameter must be used in combination with the [max_syslog_file_count](./1410.max-syslog-file-count.md) parameter. The following table describes the combinations of these two parameters.

|  | max_syslog_file_time = 0 | max_syslog_file_time > 0  |
|---|----------------------|---------------------------|
| **max_syslog_file_count = 0** | Archive logs are not cleared. This combination applies to scenarios with sufficient disk capacities. | Archive log retention is restricted only by time. If the retention period of archive logs exceeds the specified threshold, the logs are deleted.  |
| **max_syslog_file_count > 0** | Archive log retention is restricted only by space. If the number of archive log files exceeds the value of `max_syslog_file_count`, archive logs are deleted starting from the earliest ones. | Archive log retention is restricted by both time and space. This is the recommended optimal configuration. |
