# proxy_route_policy

`proxy_route_policy` specifies the routing strategy for weak-consistency read requests in OceanBase Database Proxy (ODP), which defines the backend server to which client requests are routed for processing.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <ul>
  <li><p>The <code>TARGET_REPLICA_TYPE_WITH_LEADER</code>, <code>TARGET_REPLICA_TYPE_FOLLOWER_FIRST</code>, <code>TARGET_REPLICA_TYPE_FOLLOWER_ONLY</code>, and <code>WEAKREAD_WEIGHT_LOAD_BALANCE</code> values are added in ODP V4.3.2. </p></li>
  <li><p>The parameter value is case-insensitive. </p></li>
  <li><p>If you specify a value beyond the value range, the setting can be successful but does not take effect. In this case, ODP uses the default routing strategy for weak-consistency read requests. </p></li>
  </ul>
</main>

|  Attribute    | Description     |
|----------|---------|
| Parameter type | String |
| Default value | '', which indicates an empty string     |
| Value range | <ul><li>Empty string: The default routing strategy (`MERGE_IDC_ORDER`) of ODP is used. In this strategy, weak-consistency read requests can be routed to followers and read-only replicas. </li><li><code>FOLLOWER_FIRST</code>: Read requests are preferentially routed to followers. If all the followers are unavailable, the requests are routed to the leader. </li><li><code>FOLLOWER_ONLY</code>: Read requests are routed only to followers. If all the followers are unavailable, the connection to the client is terminated. </li><li><code>UNMERGE_FOLLOWER_FIRST</code>: Read requests are preferentially routed to a follower of which the cluster is not in a major compaction. </li><li><code>TARGET_REPLICA_TYPE_WITH_LEADER</code>: Read requests are routed to specified replicas. In this strategy, the leader and followers have the same prority. The replica type is specified by <code>route_target_replica_type</code>. </li><li><code>TARGET_REPLICA_TYPE_FOLLOWER_FIRST</code>: Read requests are routed to specified replicas and to followers preferentially. If all specified followers are unavailable, read requests are routed to the leader. The replica type is specified by <code>route_target_replica_type</code>. </li><li><code>TARGET_REPLICA_TYPE_FOLLOWER_ONLY</code>: Read requests are routed to specified followers. If all specified followers are unavailable, the connection to the client is terminated. The replica type is specified by <code>route_target_replica_type</code>. </li><li><code>WEAKREAD_WEIGHT_LOAD_BALANCE</code>: Load-balanced routing is performed based on weights. You can use specify the <code>weakread_weight_zone</code> parameter to set a weight for each zone in the cluster. </li></ul> |
| Effective upon ODP restart | No |

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>When <code>route_target_replica_type</code> is set to <code>ColumnStore</code>, ODP routes read requests only to columnstore replicas instead of the leader. </p>
</main>
