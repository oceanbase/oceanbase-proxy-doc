# OceanBase Database Proxy Community Edition V4.3.5

## V4.3.5

### Version information

* Release date: August 15, 2025

* Version: V4.3.5

* RPM version: obproxy-ce-4.3.5.0-3

### Version description

ODP 4.3.5 is the latest version in the ODP 4.3.x series. It is recommended for offline business scenarios such as POC testing and production. This version introduces new features such as string-type routing, column value relationship inference for partition keys, multi-statement transaction routing, and month function routing, enhancing core routing capabilities. It also supports session connection pools, improving routing performance in short connection scenarios. The error logs when the maximum number of connections is exceeded are refined, enhancing diagnostic usability. For the RPC proxy, the logic for determining single-partition tables is optimized, improving routing accuracy in OBKV scenarios. New show commands are added to display object information, enhancing monitoring capabilities and operational usability.

### Key features

#### SQL proxy

##### Enhanced routing capabilities

* String-type routing

   OceanBase Database now supports the String type, allowing key, range columns, and list columns partitioning. ODP V4.3.5 synchronizes this support, enabling accurate routing for String-type partitions.

* Column value relationship inference for partition keys

   ODP parses SQL to extract routing information, supporting only conditions like `C1 = xxx` (where C1 is a partition key). It cannot correctly parse conditions like `C1 = C2 and C2 = xxx` that require inferring column value relationships, leading to random routing. ODP V4.3.5 introduces column value relationship inference for partition keys, enabling accurate routing for statements like `C1 = C2 and C2 = xxx` by correctly extracting partition key values and calculating partitions.

* Multi-statement transaction routing

  For multi-statement transactions started with `BEGIN` or `START TRANSACTION` (e.g., `BEGIN; xx; xx; COMMIT`), ODP routes based on the first SQL statement.

* Month function routing

   ODP V4.3.4 supports partitioning keys defined as function expressions in CREATE TABLE statements, accurately parsing and converting these expressions to ensure partition calculation accuracy. ODP V4.3.5 further introduces accurate routing for the month function.

* Optimized routing logic after hint parsing failure

   When complex hints like `/*+index(db.lna_n_biz_lock_080 primary) */` are present in SQL, ODP may fail to parse routing information, leading to inaccurate routing. ODP V4.3.5 optimizes the parsing logic for SQL with complex hints, allowing it to skip hints and continue parsing partition information for accurate routing.

##### Session connection pool

ODP, as a high-performance proxy for OceanBase Database, excels in long connection scenarios. However, in short connection scenarios, its routing performance is suboptimal due to two main factors:

* Frequent TCP connection establishment and closure between ODP and OBServer nodes.

* Synchronization of database and system variables when switching OBServer nodes for routing.

To enhance routing performance in short connection scenarios, ODP V4.3.5 introduces session-level connection pooling. This reduces the number of system calls like accept and minimizes connection latency, ultimately optimizing performance.

##### Improved usability

OceanBase Database allows control over the maximum number of connections per tenant through various configuration parameters and system variables. When this limit is exceeded, ODP logs `too many connections`, making it difficult to identify which parameter caused the issue. ODP V4.3.5 refines and differentiates error logs in `obproxy_diagnosis.log` and `obproxy_error.log`, enhancing diagnostic usability.

#### RPC proxy

##### Internal object management commands

ODP's RPC proxy involves numerous internal caches during request routing. Expired or incorrect cache content can cause stability issues. Diagnosing these issues via logs is time-consuming and unsuitable for production environments. ODP V4.3.5 introduces show commands to display OBKV-related internal object information such as rpcRequest, tabletGroup, globalIndex, QuerySync, TabletLS, and Ctx, improving operational usability.

##### Enhanced usability

ODP V4.3.5 adds statistics like RPC connection information and net_entry to the Prometheus port, enhancing monitoring capabilities for the RPC proxy.

##### Optimized single-partition table detection logic

ODP determines if a table is non-partitioned or single-partitioned based on `part_num = 1`. However, it cannot distinguish between the two. In partition split scenarios, tables created by default are single-partitioned, but ODP may misidentify them as non-partitioned. Non-partitioned and single-partitioned tables have different `tablet_id` values. In OBKV scenarios, if the `tablet_id` is not properly filled (non-partitioned tables default to `0`), OceanBase Database will return an error. ODP V4.3.5 optimizes the logic for detecting single-partition tables. If a single-partition table is misidentified as non-partitioned, ODP retries based on the OB_SCHEMA_ERROR information returned by OceanBase Database and routes the request as a single-partition table.

### Supported OceanBase Database versions

OceanBase Database V4.x, V3.x, and earlier are supported. The recommended ODP version varies based on the OceanBase Database version you use:

* If you use OceanBase Database V3.x or earlier, we recommend that you use ODP V3.x.

* If you use OceanBase Database V4.x, we recommend that you use ODP V4.3.5.

### Bug fixes

* Fixed the issue where an exception of insufficient memory is triggered when ODP processes the response from an OBServer node, causing a core dump.

* Fixed the issue where after a table is dropped and rebuilt with the same name but different partition types, an error of `-4002` is returned when data is inserted.

* Fixed the memory leak issue in the SQLMonitorInfo module.

* Fixed the issue where an error of `4723` is returned when querying a range-partitioned table after the partition structure is changed.

* Fixed the issue where the long connections of downstream requests are not released after an OBI instance is dropped.

* Fixed the issue where ODP fails to perform a hot upgrade.

* Fixed the issue where, when a specified zone is switched in the specified zone routing scenario, the new zone cannot be routed to because the tenant has no traffic and the cache has not been updated.

* Fixed the issue where, after the machines of a specified zone are replaced in the read-only address routing scenario, the newly online machines are blacklisted and cannot be whitelisted.

* Fixed the issue where, when building a batch tableQuery through LSOP, an error is returned by the getOperationRow function when all columns are obtained and decomposed into multiple LSOP requests to be sent to different log streams.

* Fixed the issue where, when connecting to ODP through a Go client, an error of `-4016` is returned when the TestPrimaryAndGlobalIndexNoPartition query is executed.

* Fixed the issue where the OB_RPC_TABLE_IGNORE_FIELD parameter consumes excessive memory.

* Fixed the issue where, when an OBServer node cannot return results due to an exception, ODP cannot read the backend results due to memory allocation restrictions, causing the partition subrequests to be unable to be cleaned up and the memory occupied by the requests to be unable to be recycled.

* Fixed the issue where, when the OBServer node returns a response that does not conform to the specification in the one-write-two-read scenario, ODP does not intercept the exception and a core dump occurs.

* Fixed the issue where, in OceanBase Database 2.0, after the memory allocation in ODP fails, the protocol parsing fails and the MySQL protocol is mistakenly used, causing an error of `-4103`.

* Fixed the issue where, when the connection allowlist verification fails, the diagnostic logs are not recorded in time.

* Fixed the issue where, when a non-partitioned table is split into a partitioned table, ODP incorrectly identifies the table type and returns an error of `-4002`.
