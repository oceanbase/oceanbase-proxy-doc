# ODP Enterprise Edition V4.3.4

## V4.3.4

### Version information

* Release date: April 25, 2025

* Version: V4.3.4

* RPM version: obproxy-ce-4.3.4.0-1

### Version overview

ODP V4.3.4 is the latest version in the ODP 4.3.x series. It is recommended for use in POC testing and production environments for both cloud and on-premises businesses. The SQL proxy has been enhanced with new features such as support for Asian character sets and collations, routing based on functions as partition keys, and improved core routing capabilities. It also optimizes routing strategies for replication tables and requests exceeding 4K, reduces remote routing, and improves routing performance. The global configuration items for protocols between ODP and OceanBase Database have been unified to enhance usability. The RPC proxy now supports accurate routing for single-partition tables and atomic retrieval of partition information, enhances routing capabilities, and improves the congestion handling process. It also asynchronously retrieves ODP ls_id information to further improve system stability.

### Key features

#### SQL proxy

##### Enhanced routing capabilities

* Support for Asian character sets and collations

  ODP V4.3.4 now fully supports Asian character sets such as ujis, euckr, cp932, and eucjpms, along with their corresponding collations.

* Optimized routing for replication tables in JOIN operations

  In previous versions, ODP would randomly route requests to any OBServer node when a replication table was involved in a JOIN operation. This could result in remote routing if the replication table was the first table in the JOIN, leading to performance issues. ODP V4.3.4 addresses this by adjusting the routing strategy: if the first table in a JOIN operation is a replication table, ODP will use the JOINed tables for routing instead of random routing, thereby mitigating performance issues caused by remote routing.

* Support for functions as partition keys

  Previously, ODP could not accurately route requests when a function expression was used as a partition key during table creation, leading to partition calculation failures. ODP V4.3.4 now identifies and parses function expressions in partition keys, ensuring accurate partition calculations.

* Routing for requests exceeding 4K

  In versions prior to V4.3.4, the default value of `request_buffer_length` was `4KB`. For requests exceeding 4KB that had not yet reached the routing information, ODP would randomly route them, potentially leading to remote routing and significant performance impact. To address this, ODP V4.3.4 increases the default value of `request_buffer_length` to `8KB`, ensuring accurate routing for requests exceeding 4KB.

##### Improved protocol configuration usability

ODP V4.3.4 introduces a new global configuration item, `server_protocol`, to explicitly control the protocol type between ODP and OceanBase Database. Previously, the protocols were controlled by `enable_ob_protocol_v2` and `enable_compression_protocol`. After ODP V4.3.1 introduced performance optimizations for standalone mode, the protocol became adaptive and no longer controlled by configuration items. This led to inconsistencies between the actual protocol type used and the configuration item values, making it difficult to accurately identify the current protocol type during troubleshooting. The addition of `server_protocol` in ODP V4.3.4 enhances the usability of protocol configuration by providing a clear and explicit way to control the protocol type.

#### RPC proxy

##### Enhanced routing capabilities

* Accurate routing for single-partition tables

  Previously, ODP could not accurately determine whether a table was a partitioned or non-partitioned table. In single-partition table scenarios, routing through the RPC proxy could result in routing errors. ODP V4.3.4 optimizes the logic to retry routing based on error information provided by the OBServer node, ensuring accurate routing for single-partition tables.

* Atomic retrieval of partition information

  Previously, ODP retrieved table information through multiple internal requests, which lacked atomicity and could lead to inconsistent table information. If inconsistencies occurred, partition calculations would fail. ODP V4.3.4 optimizes the logic to include real-time validation and retries for retrieved table information, ensuring accurate routing.

##### Enhanced congestion handling process

ODP V4.3.4 introduces asynchronous processing for RPC requests, isolating the request processing state machine from the OBServer node's network. This allows the OBServer node's state changes and congestion handling process to operate independently. OBKV requests strictly depend on the calculated partition information and corresponding routing information for SQL forwarding. The high availability capability is not fully developed and needs to be improved by adopting the congestion handling strategies from the ODP SQL proxy. This ensures that requests are never forwarded to an abnormal OBServer node under any circumstances.

##### Asynchronous retrieval of ODP ls_id information

Starting from ODP V4.3.1, the retrieval of ls_id information is synchronized and depends on the retrieval of tablet_id information, making the overall SQL processing relatively complex. Additionally, the need to query internal tables of the OceanBase cluster increases the pressure on the sys tenant of the OceanBase cluster. To address this, ODP V4.3.4 asynchronously decomposes the ls_id retrieval process. For LSOP requests, it introduces an asynchronous step to retrieve tablet_id information.

### Supported OceanBase Database versions

ODP V4.3.4 is compatible with OceanBase Database 4.x, 3.x, and lower versions. The recommended ODP version depends on the OceanBase Database version in use:

* For OceanBase Database 3.x and lower versions, it is recommended to use ODP 3.x.

* For OceanBase Database 4.x, it is recommended to use ODP V4.3.4.

### Bug fixes

* Fixed the issue where ODP fails to connect to a read-only endpoint on AWS.

* Fixed the issue where ODP fails to parse SQL statements following the `--` comment in a line break scenario.

* Fixed the issue where DBMS_LOB.READ times out and returns the business error `write clob error`.

* Fixed the issue where ODP fails to start in IPv6 mode on ARM.

* Fixed the issue where, when a default partition exists, SQL requests are not randomly distributed as expected when the partition key is missing in a partitioned table.

* Fixed the issue where, when a bypass import operation is performed by using ODP to connect to a cluster, the `4016` error is returned when the parameter is incorrectly specified.

* Fixed the issue where, when a user variable contains the `value` keyword, the PS routing is inaccurate.

* Fixed the issue where, when a request exceeding 4 KB is involved in a transaction, the connection is disconnected during parsing and retry.

* Fixed the issue where, when OceanBase Database 2.0 and the compression protocol are disabled, no result is returned when the PS protocol is used.

* Fixed the issue where, when the `kill query sessionid` statement is executed in the sys tenant, the SQL statement executed in a business tenant cannot be terminated.

* Fixed the issue where, when the `join` keyword is present in a string value in the WHERE clause, the partition information is incorrectly parsed, and the routing is inaccurate.

* Fixed the issue where, when data is inserted into a single-partition table by using an RPC proxy, the `4016` error is returned.

* Fixed the issue where, when a manual partition split operation is performed, ODP returns the `-5627` error.

* Fixed the issue where, during the initial stage of batch insert pressure testing, a large number of `routed to the wrong server` errors are returned.

* Fixed the issue where, after a node is restarted, the client is disconnected and an error is returned.

* Fixed the issue where, when the ycsb tool is used to execute the batch checkAndInsUp operation, the `unknown errcode: -10652` error is returned.

* Fixed the issue where, when a global index is queried, the `OB_ERR_KV_GLOBAL_INDEX_ROUTE` error is returned.

* Fixed the issue where, after data is migrated, ODP returns the `-5150` error for a global index, causing the client to continuously reconnect.
