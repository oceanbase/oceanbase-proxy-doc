# ODP Enterprise Edition V4.3.4

## V4.3.4

### Version information

* Release date: April 25, 2025

* Version: V4.3.4

* RPM version: obproxy-ce-4.3.4.0-1

### Version overview

ODP 4.3.4 is the latest version in the ODP 4.3.x series. It is recommended for POC testing and production in both cloud and on-premises environments. The SQL proxy has been enhanced with support for routing based on Asian character sets and collations, as well as routing based on functions as partition keys. It also improves core routing capabilities, optimizes routing strategies for replication tables and requests exceeding 4K, reduces remote routing, and enhances routing performance. Additionally, it unifies global configuration items for protocols between ODP and OceanBase Database, improving protocol configuration usability. The RPC proxy now supports accurate routing for single-partition tables and atomic retrieval of partition information, enhances routing capabilities, and improves the congestion handling process. It also asynchronously retrieves ODP ls_id information, further enhancing system stability.

### Key features

#### SQL proxy

##### Enhanced routing capabilities

* Expanded character set support

  ODP 4.3.4 now fully supports Asian character sets, including ujis, euckr, cp932, and eucjpms, along with their corresponding collations.

* Optimized routing for JOIN operations involving replicated tables

  In previous versions, ODP would randomly route requests to any OBServer node when a replicated table was involved in a JOIN operation. This could lead to remote routing, where the request was routed to a non-replicated or non-leader node, negatively impacting performance. ODP 4.3.4 addresses this by adjusting the routing strategy: if the first table in a JOIN operation is a replicated table, ODP will use the joined table for routing instead of random routing, thereby mitigating performance issues caused by remote routing.

* Support for functions as partition keys

  Previously, ODP could not accurately calculate partitions when a function expression was used as the partition key during table creation, leading to routing inaccuracies. ODP 4.3.4 now parses and converts function expressions in partition keys, ensuring accurate partition calculations.

* Routing for requests exceeding 4K

  In versions prior to ODP 4.3.4, the default value for `request_buffer_length` was `4KB`. For requests exceeding 4KB that had not yet been parsed for routing information, ODP would randomly route the request, potentially leading to remote routing and significant performance degradation. To address this, ODP 4.3.4 increases the default value of `request_buffer_length` to `8KB`, ensuring accurate routing for requests exceeding 4KB.

##### Improved protocol configuration usability

ODP 4.3.4 introduces a new global configuration item, `server_protocol`, to explicitly control the protocol type between ODP and OceanBase Database. This replaces the previous approach where the protocol type was adaptive and not directly controllable by configuration items. This change enhances the usability of protocol configuration by providing a clear and direct way to specify the protocol type.

#### RPC proxy

##### Enhanced routing capabilities

* Accurate routing for single-partition tables

  In previous versions, ODP could not accurately determine whether a table was a partitioned or non-partitioned table. This led to potential routing errors when routing single-partition tables through the RPC proxy. ODP 4.3.4 optimizes this by retrying routing based on error feedback from OBServer nodes, ensuring accurate routing for single-partition tables.

* Atomic retrieval of partition information

  Previously, ODP retrieved table information through multiple internal requests, which lacked atomicity and could lead to inconsistent table information. This could result in partition calculation failures. ODP 4.3.4 introduces real-time validation and retries for retrieved table information, ensuring accurate routing.

##### Enhanced congestion handling process

ODP 4.3.4 now asynchronously processes RPC requests, isolating the request processing state machine from OBServer node network changes. This allows the OBServer node's state changes and congestion handling process to operate independently. For OBKV requests, which strictly rely on calculated partition and routing information for SQL forwarding, the high availability capabilities are enhanced by adopting strategies from the SQL proxy to ensure that requests are never forwarded to an abnormal OBServer node.

##### Asynchronous retrieval of ODP ls_id information

Starting from ODP 4.3.1, the retrieval of ls_id information became synchronous and dependent on tablet_id retrieval, complicating SQL processing and increasing pressure on the sys tenant of OceanBase clusters. ODP 4.3.4 addresses this by asynchronously decomposing the ls_id retrieval process and adding asynchronous tablet_id retrieval steps for LSOP requests.

### Supported OceanBase Database versions

ODP 4.3.4 is compatible with OceanBase Database 4.x, 3.x, and lower versions. The recommended ODP version depends on the OceanBase Database version used:

* For OceanBase Database 3.x and lower versions, it is recommended to use ODP 3.x.

* For OceanBase Database 4.x, it is recommended to use ODP V4.3.4.

### Bug fixes

* Fixed the issue where ODP could not connect to a read-only endpoint on AWS.

* Fixed the issue where ODP failed to parse SQL statements following "--" in scenarios where "--" was used as a comment and the line was subsequently broken.

* Fixed the issue where DBMS_LOB.READ timed out and returned the business error `write clob error`.

* Fixed the issue where ODP failed to start in IPv6 mode on ARM-based systems.

* Fixed the issue where, in scenarios where a partitioned table lacked a partitioning key and a default partition existed, SQL requests were not evenly distributed as expected.

* Fixed the issue where, when using ODP to connect to a cluster for direct load, an error `4016` was returned when the parameter was incorrectly specified.

* Fixed the issue where, when a user variable contained the keyword `value`, the PS routing was inaccurate.

* Fixed the issue where, in transactions exceeding 4 KB, the connection was disconnected during parsing and retrying.

* Fixed the issue where, when OceanBase Database 2.0 and the compression protocol were disabled, no results were returned under the PS protocol.

* Fixed the issue where, when executing `kill query sessionid` in the sys tenant, the SQL statement executed in a business tenant could not be terminated.

* Fixed the issue where, when the WHERE condition contained the `join` keyword in a string value, the partition information parsing was incorrect, leading to inaccurate routing.

* Fixed the issue where, when inserting data into a single-partition table through an RPC proxy, an error `4016` was returned.

* Fixed the issue where, in manual partition splitting scenarios, ODP returned the error `-5627`.

* Fixed the issue where, during the initial phase of batch insert pressure testing, a large number of errors `routed to the wrong server` were returned.

* Fixed the issue where, after a node restart, the client disconnected and an error was returned.

* Fixed the issue where, when executing the batch checkAndInsUp operation using the YCSB tool, an error `unknown errcode: -10652` was returned.

* Fixed the issue where, when querying using a global index, the error `OB_ERR_KV_GLOBAL_INDEX_ROUTE` was returned.

* Fixed the issue where, after migration, a global index returned the error `-5150` in ODP, causing the client to continuously reconnect.
