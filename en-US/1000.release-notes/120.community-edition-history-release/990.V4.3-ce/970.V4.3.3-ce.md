# ODP Community Edition V4.3.3

* Version: V4.3.3

* RPM version: obproxy-ce-4.3.3.0-5

### Version location

ODP V4.3.3 is the latest version in the ODP 4.3.x series. It is recommended for cloud and on-premises businesses for POC testing and production. The SQL proxy has been enhanced with read/write separation capabilities between primary and standby databases. This allows cloud users to achieve read/write separation using a single connection string, thereby improving the product's capabilities. Additionally, the routing of queries to replicated tables and weak reads within transactions has been optimized to better meet the routing needs of users for specific tables and scenarios. ODP V4.3.3 now supports more character sets and collations, including utf16le, sjis, dec8, utf8mb4_german2_ci, and HKSCS. It also extends support for accurate routing of expressions such as to_days() and timestamp. The routing capabilities have been significantly enhanced. Monitoring information such as PS cache and routing details has been enriched to improve diagnostic usability. Multiple protocol-related issues have been fixed to enhance stability. For the RPC proxy, different authentication logic is supported for users in cloud and on-premises environments, and the Auth authentication mechanism has been improved. OBKV-Redis protocol commands have been added, and their processing logic has been optimized to improve performance. ODP V4.3.3 is now fully compatible with Rocky Linux 9.

### Key features

#### SQL proxy

##### Read/write separation between primary and standby databases

Currently, cloud platforms support business disaster recovery across regions, but the flexibility of ODP is not fully utilized. In addition to database switching, other scenarios require switching domain names. As the number of users of primary and standby databases in the cloud increases, it is necessary to enhance the product capabilities of primary and standby databases to support read/write separation and primary/standby switching using a single connection string.

ODP V4.3.3 introduces the read/write separation feature between primary and standby databases. This allows automatic login to the primary and standby clusters without changing the user's login connection string. It also supports automatic read/write separation across primary and standby clusters. To reduce bandwidth costs across regions, ODP and OceanBase Database use a compression protocol.

The read/write separation feature between primary and standby databases is applicable only to the primary/standby tenant architecture of OceanBase Database 4.x. It supports the eventual consistency of weak read requests.

##### Enhanced routing

OceanBase Database Proxy (ODP) V4.3.3 is the latest version of the ODP V4.3.x series and is recommended for on-cloud and on-premises business in a proof of concept (POC) test or production environment. The SQL proxy allows an on-cloud user to enable read/write splitting between the primary and standby tenants by using one connection string, thus enriching the capabilities of the primary and standby tenants. Routing capabilities are improved in the following ways: replicated table-based routing and routing for weak-consistency reads within a transaction are optimized to meet your requirements for routing of special tables in specific scenarios; more character sets and collations such as utf16le, sjis, dec8, utf8mb4_german2_ci, and HKSCS are supported; accurate routing is realized for the `TO_DAYS()` and `TIMESTAMP` expressions. Abundant monitoring information such as the prepared statement (PS) cache and routing information improves the usability of diagnostics. Several protocol-related issues are fixed to improve stability. ODP V4.3.3 is fully compatible with Rocky Linux 9.

  ODP V4.3.3 supports the correct routing of SQL requests in the utf16le, sjis, dec8, utf8mb4_german2_ci, and HKSCS character sets and collations.

* Optimized routing for replicated tables

  Replicated tables are suitable for read-heavy scenarios. Queries and local replica reads on replicated tables perform best. Therefore, ODP V4.3.3 adopts a random routing strategy for replicated tables. However, within a transaction, if a replicated table has been modified, random routing to a Follower node may result in the inability to read the latest modified data. To address this, ODP V4.3.3 optimizes the routing strategy by routing query requests for replicated tables to the Leader node when changes have been made to the replicated table within a transaction.

* Optimized weak read routing within transactions

  Within a transaction, if a write statement or a SELECT FOR UPDATE statement has been executed, subsequent read statements that want to read uncommitted modifications from the current transaction must use strong read routing, which is handled by ODP to route the read request to the Leader node. If the read request is set to weak read, it will be randomly routed to a Follower node. ODP V4.3.3 optimizes this logic by routing weak read statements after write requests in a transaction using the strong read strategy, i.e., routing to the Leader node.

* Extended support for accurate routing of more expressions: to_days() function, timestamp 'xxxxx' expression, and not in expression.

##### BINLOG support

* Compatibility with log_bin_basename variable and support for the show master logs syntax

* Support for configuring login credentials for the binglog service

##### Enhanced diagnostic usability

* PS cache monitoring

  In the PS protocol scenario, if a client uses a large amount of PS cache without closing it in a timely manner, it may occupy a significant amount of memory and potentially lead to performance issues. These issues are also difficult to troubleshoot. To improve the efficiency of troubleshooting PS protocol issues, ODP adds PS cache information to Prometheus monitoring, including the number and size of allocated PS caches. It periodically outputs this monitoring data externally. Additionally, ODP supports the internal SHOW PROXYPS command, allowing SQL queries to retrieve information about PS-related SQL statements, parsing results, and memory usage, thereby improving usability.

  For more information about the SHOW PROXYPS command, see [SHOW PROXYPS](../../../660.odp-command/20.odp-proprietary-commands/400.show/1000.show-proxyps.md).

* Routing information monitoring

  ODP adds statistics on various routing scenarios to Prometheus monitoring, including the number of routing requests within a transaction, the number of rerouting requests, the number of random routing requests after failed partition calculation, and the number of routing requests for global index tables. These statistics help in troubleshooting routing issues.
