## V4.3.1

### Version information

* Release date: July 1, 2024

* Version number: V4.3.1

* RPM version number: obproxy-4.3.1.0-402024062810

### Version location

ODP V4.3.1 is a long-term support (LTS) version of the ODP 4.3.x series. It is recommended for use in POC testing and production environments for both cloud and on-premises businesses. The SQL proxy has added features such as automatic routing between primary and standby databases, routing to multiple zones, ASCII character set routing, and utf8mb4_0900_ai_ci collation routing. It also supports the binlog_service_ip parameter for domain names and multiple addresses. Additionally, for single-node deployment scenarios, the routing strategy has been optimized to significantly improve performance. The RPC proxy has added the HBase Empty Family feature, improved the ObTableLSOps request types, and optimized the request protocol parsing logic and batch retrieval mode for routing information.

### Key features

#### SQL proxy

##### Support for automatic routing between primary and standby databases

In OceanBase Database 2.x and 3.x, the CLUSTER_NAME parameter corresponds to a group of primary and standby clusters. By default, users log in to the primary cluster. If a primary-standby switch occurs, the ODP automatically routes to the new primary cluster without changing the CLUSTER_NAME parameter, so no modifications to the login connection string are required. In OceanBase Database 4.x, to fully leverage the multi-tenant capabilities, physical standby databases are provided at the tenant level rather than the cluster level. This means that the primary or standby role information belongs to the tenant, not the cluster. Two different tenants may have a primary-standby relationship with each other, and the primary-standby relationship of a tenant is not recorded in the database but is maintained through an external component (OCP).

After a primary-standby switch, the business needs to modify the tenant name in the connection string to log in normally, which can affect the business. Therefore, starting from ODP 4.3.1, ODP interacts with the OCP interface to internally record the primary-standby relationships at the tenant level, associates different tenants, and manages the connection string through the service_name parameter. This shields users from the primary-standby relationships at the tenant level, achieving the same automatic routing effect as in OceanBase Database 2.x and 3.x.

For more information about automatic routing between primary and standby tenants, see [Automatic routing between primary and standby tenants](../../../600.data-routing/450.primary-and-backup-tenant-routing.md).

##### Routing to multiple zones

The `proxy_primary_zone_name` parameter in ODP supports specifying a single zone for routing, directing all requests received by ODP to the specified zone. OceanBase Database supports hybrid workloads of OLAP and OLTP, requiring ODP to route analytical requests to multiple replicas of OLAP for load balancing. Therefore, ODP V4.3.1 extends the `proxy_primary_zone_name` parameter to support routing to multiple zones.

##### Support for additional character sets and collations

OceanBase Database 4.2.4 supports the ASCII character set, TIS620 character set, and utf8mb4_0900_ai_ci collation. ODP V4.3.1 also supports routing for these character sets and collations.

##### Support for domain names and multiple addresses for binlog_service_ip

In the interaction architecture between the Binlog service and ODP, ODP sends Binlog-related SQL requests or Binlog Dump requests by first obtaining the corresponding Binlog service cluster address through the binlog_service_ip parameter and then sending the request to the specific Binlog service cluster. Currently, the binlog_service_ip parameter only supports a single IP address and does not support domain names, which is insufficient for some high-availability scenarios. ODP V4.3.1 supports domain names and multiple addresses, achieving high availability in the following scenarios:

* Load balancing (LB) addresses have different physical IP addresses in different zones.

* Automatic recovery capability when LB switches.

##### Performance optimization

Single-node deployment mode: ODP is a dedicated service proxy for OceanBase Database, with the core goal of solving routing issues in distributed clusters with multiple nodes. The routing strategy has significant advantages in distributed scenarios, but in single-node scenarios, the routing requirements are simple, and complex routing logic is unnecessary. Therefore, in ODP 4.3.1, the routing logic for single-node scenarios has been optimized to improve routing performance.

Compilation optimization: ODP V4.3.1 introduces some system compilation optimizations to further enhance performance.

In single-node mode, ODP V4.3.1 improves routing performance by 30% to 50% compared to ODP V4.3.0.

#### RPC proxy

##### Enhanced support for ObTableLSOps requests

ODP V4.3.0 introduced a new single-operation format and corresponding batch format to support the checkAndInsUp semantics and ObTableLSOps requests. ODP V4.3.1 further enhances this by supporting multiple TableOperations in LSOP, sub-request division based on log streams, and optimized performance.

##### HBase Empty Family

Currently, OceanBase Database's HBase API only supports single column families. To better support multi-column families and maintain compatibility without modifying client code in certain scenarios, such as when the client scan operation is performed with an empty column family, the concept of table groups is introduced in HBASE mode. By default, HBASE tables correspond to OceanBase Database table groups, and HBASE column families correspond to OceanBase Database tables. This approach is used to maintain compatibility with HBASE column families. In this case, the table name in the request sent from the client to ODP corresponds to the current table group name. ODP needs to support routing based on table groups to support the new HBASE mode.

### Configuration changes

|              Configuration               | Change type |                                                                        Description                                                                        |
| --------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| enable_single_leader_node_routing | New     | Controls whether to use more efficient routing rules when the tenant is deployed in a primary-replica cluster.                                                                                  |
| enable_full_link_trace            | New   | Controls whether to use the full-link trace feature to trace query execution.  |
| rpc_max_response_batch_size       | New   | Sets the maximum number of batches sent back in a single response.  |
| rpc_max_request_batch_size        | Changed  | The default value of this configuration item was updated from `5` to `20` starting from version 4.3.1.  |
| enable_standby                    | Changed     | Starting from version 4.3.1, this configuration item supports controlling whether to enable primary-standby tenant routing.                                                                                 |
| proxy_primary_zone_name           | Changed     | Starting from version 4.3.1, this configuration item supports configuring multiple zone names. |
| binlog_service_ip                 | Changed    | Starting from version 4.3.1, this configuration item supports configuring multiple IP addresses or domains.   |
| enable_strict_stat_time           | Changed    | Starting from version 4.3.1, the default value of this configuration item was updated from <code>True</code> to <code>False</code>.   |

### Supported OceanBase Database versions

OceanBase Database 4.x, 3.x, and earlier versions are supported. The recommended ODP versions vary based on the OceanBase Database version used:

* For OceanBase Database 3.x and earlier, we recommend using ODP V3.2.11.

* For OceanBase Database 4.x, we recommend using ODP V4.3.1 (LTS version).
