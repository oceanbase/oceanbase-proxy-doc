## V4.3.1

### Version information

* Release date: July 1, 2024

* Version: V4.3.1

* RPM version: obproxy-4.3.1.0-402024062810

### Version location

ODP V4.3.1 is the long-term support (LTS) version of the ODP 4.3.x series. It is recommended for use in POC testing and production environments, both in the cloud and on-premises. The SQL proxy now supports automatic routing between primary and standby databases, routing to multiple zones, ASCII character set routing, and utf8mb4_0900_ai_ci collation routing. It also supports domain names and multiple addresses for the binlog_service_ip parameter. Additionally, the routing strategy has been optimized for single-node deployments, significantly improving performance. The RPC proxy now supports the HBase Empty Family feature, enhances the ObTableLSOps request type, and optimizes the request protocol parsing logic and batch retrieval of routing information.

### Key features

#### SQL proxy

##### Automatic routing between primary and standby databases

In OceanBase Database 2.x/3.x, the CLUSTER_NAME parameter corresponds to a group of primary and standby clusters. By default, users log in to the primary cluster. If a failover occurs, the ODP automatically routes to the new primary cluster without changing the CLUSTER_NAME parameter, so no modifications to the login connection string are required. In OceanBase Database 4.x, to fully leverage the multi-tenant capabilities, physical standby databases are provided at the tenant level rather than the cluster level. This means that the primary or standby role is tenant-specific, and two different tenants can be primary and standby to each other. Additionally, the primary and standby relationship of a tenant is not recorded in the database but is maintained through an external component (OCP).

After a primary-standby switch, the tenant name in the connection string must be modified for the application to log in normally, which can impact the business. Starting from ODP 4.3.1, ODP interacts with the OCP interface to internally record the primary-standby relationship at the tenant level, associates different tenants, and manages connections through the service_name parameter. This shields users from tenant-level primary-standby awareness, achieving the same automatic routing effect as in OceanBase Database 2.x/3.x.

For more information about automatic primary-standby routing, see [Automatic primary-standby routing](../../../600.data-routing/450.primary-and-backup-tenant-routing.md).

##### Routing to multiple zones

The `proxy_primary_zone_name` parameter in ODP supports specifying a single zone for routing, directing all received requests to the specified zone. OceanBase Database supports mixed OLAP and OLTP workloads, requiring ODP to route analytical requests to multiple OLAP replicas for load balancing. Therefore, ODP V4.3.1 extends the `proxy_primary_zone_name` parameter to support routing to multiple zones.

##### Character set and collation extensions

OceanBase Database 4.2.4 supports the ASCII character set, TIS620 character set, and utf8mb4_0900_ai_ci collation. ODP V4.3.1 also supports routing for these character sets and collations.

##### Domain name and multiple addresses for binlog_service_ip

In the interaction architecture between the Binlog service and ODP, ODP first obtains the corresponding Binlog service cluster address through the binlog_service_ip parameter before sending requests to the specific Binlog service cluster. Currently, binlog_service_ip only supports a single IP address and does not support domain names, which limits its applicability in high-availability scenarios. ODP V4.3.1 supports domain names and multiple addresses, achieving high availability in the following scenarios:

* Load balancing (LB) addresses have different physical IP addresses in different zones

* Automatic recovery capability during LB switching

##### Performance optimization

Single-node deployment mode: ODP is a dedicated service proxy for OceanBase Database, with the core goal of solving routing issues in distributed clusters with multiple nodes. The routing strategy has significant advantages in distributed scenarios, but in single-node scenarios, routing requirements are simple, and complex routing logic is unnecessary. Therefore, ODP V4.3.1 optimizes the routing logic for single-node scenarios, significantly improving routing performance.

Compilation optimization: ODP V4.3.1 introduces some system compilation optimizations, further enhancing performance.

In single-node mode, ODP V4.3.1 improves routing performance by 30% to 50% compared to ODP V4.3.0.

#### RPC proxy

##### Enhanced ObTableLSOps request functionality

ODP V4.3.0 introduced a new single-operation format and corresponding batch format to support the checkAndInsUp semantic and ObTableLSOps requests. ODP V4.3.1 further enhances this by supporting multiple TableOperations in LSOP requests, subrequest division based on log streams, and optimized performance.

##### HBase Empty Family

Currently, OceanBase Database's HBase API only supports single column families. To better support multi-column families and ensure compatibility without modifying client code in certain scenarios (such as when a client scan includes an empty column family), the concept of table groups is introduced in HBase mode. By default, an HBase table corresponds to an OceanBase table group, and an HBase column family corresponds to an OceanBase table. This approach is used to maintain compatibility with HBase column families. In this case, the table name in the request sent from the client to ODP corresponds to the current table group name. ODP must support routing to table groups to enable this new HBase mode.

| rpc_max_response_batch_size       | New   | Sets the maximum number of batches in a single response.  |

### Supported OceanBase Database versions

OceanBase Database V4.x, V3.x, and earlier versions are supported. The recommended ODP version depends on the OceanBase Database version you use:

* If you use OceanBase Database V3.x or earlier, we recommend that you use ODP V3.2.11.  2

* If you use OceanBase Database V4.x, we recommend that you use ODP V4.3.1 (LTS version).
