# ODP Enterprise Edition V4.3.4

## V4.3.4 hotfix1

### Version information

* Release date: May 26, 2025

* Version: V4.3.4 hotfix1

* RPM version: obproxy-4.3.4.0-332025052117

### Purpose of the release

To support the use of secondary partitioning and time-series table routing features in OBKV-HBase of OceanBase Database V4.3.5.2 and later versions.

* Fixed the issue where an error message was displayed when the table did not exist in OBKV.

## V4.3.4

### Version information

* Release date: April 18, 2025

* Version: V4.3.4

* RPM version: obproxy-4.3.4.0-262025041714

### Version location

ODP 4.3.4 is the latest version in the ODP 4.3.x series. It is recommended for POC testing and production use in both cloud and on-premises environments. SQL proxy enhancements include support for Asian character sets and collations, routing based on functions as partition keys, improved core routing capabilities, optimized routing strategies for replication tables and requests exceeding 4K, reduced remote routing, and enhanced routing performance. Additionally, global configuration items for protocols between ODP and OceanBase Database have been unified to improve usability. RPC proxy enhancements include accurate routing for single-partition tables, atomic partition information retrieval, improved congestion handling processes, asynchronous retrieval of ODP ls_id information, and further system stability improvements.

### Key feature descriptions

#### SQL proxy

##### Enhanced routing capabilities

* Expanded character set support

  ODP 4.3.4 now fully supports Asian character sets, including ujis, euckr, cp932, and eucjpms, along with their corresponding collations.

* Optimized routing for JOIN operations involving replicated tables

  In previous versions, ODP would randomly route requests to any OBServer node when a replicated table was involved in a JOIN operation. If the replicated table was the first table in the JOIN, it could route the request to a non-replicated or non-leader node, resulting in remote routing and impacting overall performance. ODP V4.3.4 optimizes this by adjusting the routing strategy: when the first table in a JOIN is a replicated table, ODP uses the joined table for routing instead of random routing, thereby mitigating performance issues caused by remote routing.

* Support for functions as partition keys

  In previous versions, if a function expression was used as a partition key during table creation, partition calculation would fail, leading to inaccurate routing. ODP V4.3.4 addresses this by parsing and converting function expressions in partition keys, ensuring accurate partition calculation.

* Routing for requests exceeding 4K

  In versions prior to ODP V4.3.4, the `request_buffer_length` parameter had a default value of `4KB`. For requests exceeding 4KB that had not yet reached the routing information, ODP would randomly route the request due to parsing failures, potentially leading to remote routing and significant performance impact. To address this, ODP V4.3.4 increases the default value of `request_buffer_length` to `8KB`, ensuring accurate routing for requests exceeding 4KB.

##### Improved protocol configuration usability

ODP previously used two parameters, `enable_ob_protocol_v2` and `enable_compression_protocol`, to control the protocol between ODP and OceanBase Database. After ODP V4.3.1 introduced performance optimizations for standalone mode, the protocol became adaptive and no longer controlled by configuration parameters. This led to inconsistencies between the actual protocol used and the configured values, making it challenging to identify the current protocol during troubleshooting. ODP V4.3.4 introduces a new global parameter, `server_protocol`, to explicitly define the protocol between ODP and OceanBase Database, enhancing usability.

#### RPC proxy

##### Enhanced routing capabilities

* Accurate routing for single-partition tables

  In previous versions, ODP could not accurately determine whether a table was partitioned or not. In single-partition table scenarios, routing through the RPC proxy could result in routing errors. ODP V4.3.4 optimizes this by retrying routing based on error information provided by the OBServer node, ensuring accurate routing for single-partition tables.

* Ensuring atomicity in partition information retrieval

  In previous versions, ODP retrieved table information through multiple internal requests, which lacked atomicity and could lead to inconsistent table information. If inconsistencies occurred, partition calculations would fail. ODP V4.3.4 addresses this by adding real-time validation and retries for retrieved table information, ensuring accurate routing.

##### Improved congestion handling processes

ODP's RPC proxy now supports asynchronous processing of RPC requests. During processing, the request state machine and OBServer node network are isolated, allowing the OBServer node's state changes and congestion handling processes to operate independently. OBKV requests strictly rely on calculated partition and routing information for SQL forwarding, which limits high availability. To address this, ODP V4.3.4 borrows strategies from the SQL proxy to ensure that requests are never forwarded to an abnormal OBServer node, regardless of the situation.

##### Asynchronous retrieval of ODP ls_id information

Starting with ODP V4.3.1, retrieving ls_id information became synchronous and dependent on tablet_id retrieval, complicating SQL processing and increasing pressure on the sys tenant of the OceanBase cluster. To resolve this, ODP V4.3.4 asynchronously decomposes the ls_id retrieval process. For LSOP requests, it adds asynchronous tablet_id retrieval steps.

### Supported OceanBase Database versions

ODP 4.3.4 supports OceanBase Database 4.x, 3.x, and lower versions. The recommended version depends on the OceanBase Database version in use:

* For OceanBase Database 3.x and lower, it is recommended to use ODP V3.2.11.

* For OceanBase Database 4.x, it is recommended to use ODP V4.3.1 (LTS version).

ODP V4.3.4 introduces several new features. If your environment relies on these new features, we recommend using the latest version, V4.3.4. If your environment does not rely on these new features, we recommend using the LTS version, V4.3.1.

### Bug fixes

* Fixed the issue where ODP could not connect to a read-only endpoint on AWS.

* Fixed the issue where ODP failed to parse SQL statements after `--` when `--` was followed by a line break.

* Fixed the issue where DBMS_LOB.READ timed out and the business error `write clob error` occurred.

* Fixed the issue where ODP failed to start in IPv6 mode on ARM.

* Fixed the issue where the SQL requests were not evenly distributed when the partition key was missing in a partitioned table and a default partition existed.

* Fixed the issue where the `4016` error occurred when a parameter was incorrectly written during bypass import using ODP.

* Fixed the issue where the PS routing was inaccurate when the user variable contained the `value` keyword.

* Fixed the issue where the connection was disconnected when a request larger than 4K was parsed and retried in a transaction.

* Fixed the issue where no result was returned when OceanBase Database 2.0 and the compression protocol were disabled and the PS protocol was used.

* Fixed the issue where the `kill query sessionid` statement executed in the sys tenant could not terminate an SQL statement executed in a business tenant.

* Fixed the issue where the partition information was incorrectly parsed and the routing was inaccurate when the WHERE clause contained the `join` keyword.

* Fixed the issue where the `4016` error occurred when data was inserted into a single-partition table through an RPC proxy.

* Fixed the issue where ODP returned the `-5627` error when manual partition splitting was performed.

* Fixed the issue where a large number of `routed to the wrong server` errors occurred during the initial phase of batch insert stress testing.

* Fixed the issue where the client was disconnected and an error occurred when a node was restarted.

* Fixed the issue where the `unknown errcode: -10652` error occurred when the YCSB tool executed the batch checkAndInsUp operation.

* Fixed the issue where the `OB_ERR_KV_GLOBAL_INDEX_ROUTE` error occurred when a global index was queried.

* Fixed the issue where ODP returned the `-5150` error when a global index was migrated, causing the client to continuously reconnect.
