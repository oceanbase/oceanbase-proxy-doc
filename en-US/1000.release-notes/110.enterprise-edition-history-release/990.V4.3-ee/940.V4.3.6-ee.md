# OceanBase Database Proxy Enterprise Edition V4.3.6

## V4.3.6 BP1

### Version information

* Release date: January 09, 2026

* Version number: V4.3.6 BP1

* RPM version: obproxy-4.3.6.1-212026010819

### Bug fixes

* Fixed the issue where VIPs under the PPV2 protocol did not have port information added.
* Fixed the issue where ODP connection drops occurred due to CS_ID leakage.
* Fixed the issue where an error was reported after the application started, preventing access to the OceanBase cluster.
* Fixed the issue of high time consumption for pre-executing business SQL.
* Fixed the issue where ODP logs were not controlled by log configuration (`syslog_level`), potentially leading to log loss.
* Fixed the issue where connection drops occurred during PREPARE execution in weak-consistency read scenarios.
* Fixed the issue where an error `4013` was reported during OBKV stress testing using OceanBase Database V4.3.5 and ODP V4.3.6.
* Fixed the issue where the actual log file size was max_log_file_size/2 after configuring the ODP parameter `max_log_file_size`.

## V4.3.6

### Version information

* Release date: November 10, 2025

* Version number: V4.3.6

* RPM version number: obproxy-4.3.6.0-192025110620

### Overview

ODP V4.3.6 is the latest Long-Term Support (LTS) version of ODP 4.3.x. It focuses on stability enhancements and core capability upgrades and is recommended for cloud and on-premises businesses for proof-of-concept testing and production. For SQL proxy, it adds support for the Azure PPV2 protocol to improve cloud environment compatibility; supports printing user logout log information to enhance auditing capabilities and operational observability; and optimizes the memory management mechanism, improves memory fragmentation handling logic, and supports dynamic adjustment strategies when memory exceeds the limit. It also further refines the CRASH signal interception behavior, significantly improving the operational stability of the SQL proxy. For RPC proxy, it introduces a kernel-feedback-based routing optimization mechanism that reroutes when routing information is inaccurate; supports the new HBase Put protocol to improve write performance; and adds RPC Request lifecycle management capabilities, optimizing retry logic and cross-partition sub-request processing strategies, comprehensively enhancing the reliability and performance of the RPC proxy.

### Key feature description

#### SQL proxy

**Connection management**

Under the Azure PPV2 protocol, `PP2_SUBTYPE_AZURE_PRIVATEENDPOINT_LINKID` is used to map to tenant information. The new ODP version supports parsing this field to complete the mapping, thereby supporting the PPV2 protocol under Azure.

**Stability improvements**

* Memory optimization

  The system has reviewed issues and optimization points in the ODP memory management module and optimized them in the LTS version to improve memory stability. The main contents include:

  * Optimized the memory usage of the PS module, which can easily cause memory fragmentation, avoiding memory amplification and slow recycling caused by memory fragmentation.

  * In scenarios where memory exceeds the limit, it supports dynamically increasing the ODP memory limit via signals, to avoid issues where memory alarms and new connection failures occur when the limit cannot be increased upon exceeding it.

* Optimized CRASH signal interception behavior

  The CRASH signal interception configuration is optimized through the `enable_crash_error_log` parameter. By default, it is set to `True`, allowing CRASH signal interception and printing of stack information. The parameter supports dynamic modification.

**Usability improvements**

ODP V4.3.6 supports printing user logout log information. ODP has connection diagnostic capabilities and outputs user login information and abnormal disconnection information to the `obproxy_diagnosis.log` file, but lacked record-keeping for logout information. The new version also prints information for normal user exit (`COM_QUIT`) in the log and unifies the disconnection log format, providing users with a complete and easy-to-use audit capability for login and logout.

#### RPC proxy

**Routing capability improvements**

ODP V4.3.6 supports rerouting when routing information is inaccurate, based on information fed back to ODP by OceanBase Database. OceanBase Database supports distributed capabilities, so even if a route is incorrect, an RPC call will still execute successfully. However, if ODP does not receive feedback, it will not refresh the cache, leading to continuous RPC consumption and performance degradation. To solve this, after enabling distributed routing, ODP needs to populate the `tablet_id`, and the client must add an `option_flag` field. OceanBase Database then jointly determines whether distributed capabilities are enabled based on the `option_flag` and `tablet_id`.

**Connection management**

ODP V4.3.6 supports the new HBase Put protocol. Write performance in ODP HBase scenarios was poor. Analysis revealed that most of the overhead in the OBKV layer lies in protocol parsing, routing calculation, and data conversion between the model layer and the TableAPI layer. The data format for HBase Put operations is relatively fixed, and the operation logic is also relatively simple, with no excessive computation. Therefore, the new version creates a fast path for Put operations within the OBKV framework, removing the conversion overhead at each intermediate layer, enabling immediate writing after protocol parsing is completed, thereby improving write performance.

**Stability improvements**

* Added lifecycle management for RPC requests

  RPC requests are primarily processed by three modules: `client_net_handler`, `request_sm`, and `server_net_handler`. ODP sets a `STATE` for each of these modules, and a request can only be released when all three states meet the release conditions. If the `STATE` becomes invalid due to abnormal interactions with OceanBase Database, the request may remain in memory waiting for a scheduled task to trigger, occupying memory for an extended period. The new version introduces lifecycle management for RPC requests to address this issue.

* Optimized RPC request retry logic

  When the table schema changes (for example, a TRUNCATE operation), ODP needs to asynchronously refresh the location cache. During this period, the old cache is still used, leading to a series of retry issues: frequent retries consume resources by unnecessarily sending requests to OBServer nodes; retries may end too quickly before the cache is successfully refreshed, causing the original request to still report an error; and retrying subrequests limits the recalculation of `tablet_id`, leading to retry failures. The new version improves the retry process and optimizes the retry logic to resolve these cache expiration-related problems.

* Optimized the processing strategy for cross-partition subrequests in OBKV

  When ODP receives a request, it calculates that the RPC may involve all subpartitions. For cross-partition requests, ODP uses a splitting pattern for processing. In exceptional scenarios, the parent request's task being coupled with each subrequest's `sub_request_sm` could lead to stability issues. The new version decouples parent and child requests and state machines, making them unaware of each other. This results in a simple and clear call chain, high performance, and better stability, making it easier to troubleshoot and locate issues when they occur.

**Usability improvements**

ODP V4.3.6 controls whether to print slow RPC queries and obproxy_digest logs for subrequests. When RPC requests are printed as slow or digest logs, subrequests are ignored. However, subrequests are complete RPC requests that also need to be tracked through slow logs. To avoid excessive subrequests and the high performance consumption from excessive printing, the `rpc_enable_sub_req_log` parameter is added to control the logging behavior.

### Supported OceanBase Database versions

ODP supports OceanBase Database 4.x, 3.x, and earlier versions. The recommended versions vary based on the OceanBase Database version in use:

* For OceanBase Database 3.x and earlier, we recommend using ODP V3.2.11.

* For OceanBase Database 4.x, we recommend using the latest BP version (LTS version) of ODP V4.3.6.

### Known issues

In long-running stable clusters (operating for more than 7 days) with the global unique client session ID (client_session_id_version=2) enabled, connection establishment may fail. We recommend upgrading your business to the latest version that fixes this issue.

### Bug fixes

* Fixed the issue where ODP memory usage exceeded 90% in text PS prepare scenarios, and ODP memory was released slowly after the connection was disconnected.

* Fixed the issue where ODP failed to start because no IP hostname was configured in `/etc/hosts`.

* Fixed the issue where the `odp_current_session` metric showed negative values in scenarios using `service_name` login, causing OCP to report that the number of connections exceeded the limit.

* Fixed the issue where ODP experienced memory leaks during system variable or user variable synchronization in scenarios using `COM_RESET_CONNECTION` or `COM_CHANGE_USR`.

* Fixed the issue where the getaddrinfo system call returning more than 64 IPs caused an array bounds error when storing the IPs, leading to an ODP core dump.

* Fixed the issue where DML statements with column names containing the character `#` were routed incorrectly.

* Fixed an ODP Core issue caused by out-of-bounds memory access due to insufficient stack size after adjusting the `digest_sql_length`.

* Fixed an issue where, when ODP sent multiple requests at once, the client would become stuck because ODP did not properly handle the response packets from OceanBase Database, which processed requests much faster.

* Fixed an ODP Core issue caused by SQL requests containing the `status` keyword.

* Fixed an issue where ODP parsing requests would deadlock when using a `service_name` connection and the SQL request length exceeded 16 MB.

* Fixed an issue where, in scenarios with memory leak diagnostics enabled, the `show proxymemory objpool;` command had a fixed 30-second timeout that could not be modified, preventing specific `show proxymemory objpool;` information from being displayed and hindering effective diagnosis of memory leak causes.

* Fixed an ODP Core issue caused by a stack overflow when parsing expressions like `round(9.99,-9.9)`, `round(9.99,-10)`, and `round(99.99,-20)`.

* Fixed an ODP Core issue where, when parsing requests for non-partitioned tables, ODP encountered an OB_SCHEMA_ERROR message. Upon retry, it routed the request as a single-partitioned table, but the part info was empty, causing a core dump.

* Fixed an ODP Core issue caused by concurrent execution of large requests exceeding the request buf len while synchronizing the xa_start variable.

* Fixed an issue where, when ODP's memory limit was exceeded, the proxysys tenant could not establish a connection.

* Fixed an issue where, in multi-column partitioned table scenarios, ODP failed to obtain partition information, leading to inaccurate routing.

* Fixed an issue where, after a partition split, ODP exceeded the retry count for obtaining `tablet_id` information, resulting in a 4016 error.

* Fixed an error when session information was not synchronized upon PS close or reset.

* Fixed an error during request execution where a truncate table operation changed routing information, and the cache had not been successfully updated during ODP's retry process.

* Fixed an occasional failure to shut down distributed routing capability after enabling it again, due to uncleaned thread caches.

* Fixed an issue where OceanBase Database could not respond with results due to memory issues, and ODP could not read the backend results due to limited memory allocation, causing partition sub-requests to remain unfetched and request memory to be unreclaimable.

* Fixed a `4016` error during cross-partition request execution caused by a truncate table operation.

* Fixed an issue where, when disabling `rpc_enable_congestion`, isolated RPC ports failed to recover performance within 2 minutes.

* Fixed an issue where, when disabling `rpc_enable_congestion`, nodes going offline reported a `4016` error that persisted for more than 2 minutes without recovery.

* Fixed a potential memory leak issue where `part_num` was 0 when obtaining `table_entry` in single-partitioned table routing scenarios.

* Fixed a `4016` error where, during PS close statement session state synchronization, OceanBase Database returned inaccurate transaction completion flags, causing ODP to mistakenly assume the transaction was finished.
